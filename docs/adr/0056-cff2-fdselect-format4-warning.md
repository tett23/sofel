# ADR 0056: CFF2 の FDSelect フォーマット4を互換性の警告として扱う

ステータス: 採択（未実装）

## 文脈

CFF2 の FDSelect は、各グリフが使うフォント辞書の番号を格納する。
[ADR 0021](0021-cff-outlines.md) は、HarfBuzz と互換の読み取りではフォーマット4を受け付け、FreeType と互換の輪郭取得では、この形式の表を読む必要があるときにエラーとする。
検証器では、フォントの構造上の誤りと、輪郭取得の互換性に関する制約を区別したい。

## 調査した事項

CFF2 の検証器と FreeType 互換の読み込み処理は、フォント辞書が複数あるときに FDSelect を読む。
検証器は、読み取れたフォーマット4の表に `fd_select_format4` を出した後も、範囲の順序、辞書番号の上限、末尾の番兵を検査する。
番兵は最後の範囲の直後を示すグリフ番号である。

テスト用のフォント生成器で、3グリフの辞書番号を順に `[0, 1, 1]` とした CFF2 を3個作り、FDSelect の形式だけを変えて比較した。
次の「輪郭用」は `Cff::new`、「辞書番号」は `HbCff2::fd` による結果である。

| FDSelect | 辞書番号 | 輪郭用 | sofel-validate の診断 | 終了コード |
| --- | --- | --- | --- | --- |
| 4 | 0, 1, 1 | FdSelect エラー | 警告1件 | 0 |
| 3 | 0, 1, 1 | 成功 | なし | 0 |
| 0 | 0, 1, 1 | 成功 | なし | 0 |

## 実装すること

[ADR 0021](0021-cff-outlines.md) の診断を維持する。
CFF2 の検証でフォーマット4を読み取ったこと自体は警告とし、構造上の誤りはそれぞれの診断で報告する。
実装時に CLI の終了コードを回帰テストで固定し、仕様書とロードマップに判断結果を反映する。

## 警告を解消する方法

フォントを生成し直せて、グリフごとの辞書番号を保ったまま FDSelect をフォーマット0か3で表現できる場合は、生成側でその形式を使ってフォントを再生成する。
フォーマット0はグリフごとに1バイトの辞書番号を持つ。
フォーマット3は辞書番号が1バイトで、範囲数、各範囲の先頭、番兵がそれぞれ16ビットに収まる必要がある。
どちらも辞書番号256以上をそのまま格納することはできない。
単に形式番号を書き換えると後続のデータの解釈が変わるため、表と関連するオフセットを再生成する。
再生成できない場合や、同じ割り当てを表現できる形式がない場合は、元のフォントを維持して互換性の警告を受け入れる。

## 実装しないこと

検証器によるフォントの書き換え、警告の一律非表示、FreeType 互換の輪郭取得の変更、CFF1 の診断の変更は対象外とする。

## 不変条件

1. CFF2 の FDSelect に対する `fd_select_format4` の重大度は常に Warning である。
2. 読み取り可能な入力ファイルを通常の引数で検証した場合、この警告だけなら終了コードは0であり、同時に Error があれば1である。
3. 他に問題のない CFF2 で辞書番号の割り当てを保ったまま FDSelect を形式0または3で再生成できたとき、再生成後の表からこの警告は出ない。

| 境界の入力 | 期待する結果 |
| --- | --- |
| 辞書が1個で FDSelect を省略した正常なフォント | この警告なし、終了0 |
| 辞書が2個で有効な形式4を使う | 警告、終了0 |
| 形式4の範囲を読めるが番兵がグリフ数と異なる | 警告と構造エラー、終了1 |
| 同じ2辞書への割り当てを形式0または3で記録 | この警告なし、終了0 |

## テスト設計

`inv1_fdselect_format4_severity` で診断 ID と重大度を検査する。
`inv2_validate_fdselect_exit` は表のフォントを CLI に渡し、診断と終了コードの両方を照合する。
`inv3_equivalent_fdselect` は3形式で全グリフの辞書番号を比較し、形式0と3で警告が消え、輪郭用の読み込みが成功することを確かめる。

## トレードオフ

入力を変更できない利用者にも、検証が成功したフォントで輪郭取得に失敗し得ることが伝わる。
フォントの生成側で表現を変更する場合は、辞書の割り当てと表の参照先を保つ作業が必要になる。
