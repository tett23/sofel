# ADR 0060: AAT の置換と位置調整をシェーピングに組み込む

ステータス: 採択

## 文脈

[ADR 0020](0020-shaping-foundation.md) は AAT の表を使うシェーピングを第10段階に送った。
OpenType と AAT の表を併せ持つフォントでは、両方の置換やカーニングを重ねて適用すると結果が変わる。

## 調査した事項

固定した HarfBuzz の src には hb-aat-layout.cc のほかに morx、kerx、ankr、trak、feat の表ごとの実装がある。
[既知の差の一覧](../../conformance/expected-failures.txt)では AAT の入力を個別に追跡している。

## 実装すること

sofel-read で AAT の表を検査し、sofel-shape の計画で置換と位置調整の経路を個別に選ぶ。
morx と mort、GSUB の選択、kerx、旧 kern と GPOS の選択は固定した HarfBuzz のシェーピング計画に合わせる。
feat と ltag を使った機能選択、ankr を使った位置調整、ポイントサイズを使う trak、dumber シェーパーを含む。
状態機械は入力位置と状態を別に持ち、入力を進めない遷移が続く場合も有限回で打ち切る。
表を読み始める前にオフセットと件数を検査し、適用できない表の扱いを参照実装と照合する。

## 実装しないこと

Graphite とプラットフォームのシェーパーは範囲外とする。

## 不変条件

1. 同じフェイス、文字列、方向、機能範囲、ポイントサイズに対し、グリフ ID、クラスタ、送り、オフセット、フラグが hb-shape と一致する。
2. 入力バイト列の外を読まず、循環する状態遷移でも処理が終了する。

| 境界の入力 | 判定 |
| --- | --- |
| 空文字列、1文字、合字の先頭と末尾で機能の範囲が切れる文字列 | それぞれ条件1を満たす |
| morx と GSUB、kerx と GPOS を併せ持つフォント | GPOS の kern の有無ごとに条件1を満たす |
| trak の指定サイズちょうど、その前後、ポイントサイズ未指定 | STAT の有無とサイズの各組で条件1を満たす |
| 遷移先が表の末尾を1バイト越える、入力を消費しない自己ループ | 条件2を満たす |

## テスト設計

I1_aat_shape で上表と既知の AAT 入力を hb-shape に渡し、全フィールドを比較する。
I2_aat_state で短い合成表を使って打ち切りを確かめ、表の読み取りと状態遷移をファジングする。
一致した入力から期待失敗を削除する。

## トレードオフ

置換と位置調整の選択を分けると、混在フォントを扱える一方、表の組み合わせごとにテストが要る。
