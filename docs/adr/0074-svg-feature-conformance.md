# ADR 0074: SVG の対応機能を入力と出力に分けて検証する

ステータス: 採択（未実装）

## 文脈

開発者が知りたいのは、フォント内の SVG を取り出せるか、指定したグリフを正しく描けるか、配置したグリフを SVG ページに書けるかである。
それぞれ不具合の現れる段階が違うため、機能ごとに根拠となるケースと合否を示す。
対応範囲は OT-SVG 入力の [ADR 0066](0066-color-glyph-pixels.md) と [ADR 0072](0072-color-gallery-acceptance.md)、SVG 出力の [ADR 0068](0068-vector-and-gpu-output.md) に従う。

## 調査した事項

[SVG テーブルのテスト](../../crates/sofel-read/tests/color.rs) の svg_documents は、グリフ範囲と文書のバイト列を調べる。
[カラー形式のテスト](../../crates/sofel-color/tests/color.rs) の bitmaps_and_svg は、Painter に渡した画像の形式、gzip フラグ、バイト数を調べる。
固定した chromacheck-svg.ttf のグリフ1に sofel-paint を実行すると、SVG 画像を表す命令が一つ出力された。
これらの観測からは、グリフ内の図形の位置や色は判定できない。
OpenType の SVG テーブル仕様は、フォントで扱う SVG の範囲を定めている。

## 実装すること

適合テストに Rust の検証用コマンドを置き、リポジトリ直下の `sh scripts/test-svg-conformance.sh` からローカルとコード変更時の CI で同じケースを実行する。
コマンドは下表の機能を列挙した台帳を読み、標準出力に機能 ID、ケース ID、入力または出力の別、期待値の出典、結果を出す。
必須ケースの失敗、未実装、未実行、参照値の欠落は理由付きで表示し、一つでもあれば非ゼロで終了する。
開発中も全件の結果を出し、対応済みの機能と残りを確認できるようにする。

| 機能 ID | 必須のケース | 合格を判断する観測 |
| --- | --- | --- |
| in-document | 平文と gzip、同一文書内の異なる2グリフ、範囲外の ID | 対象要素、gzip 展開後の内容、双方の形式で同じ画素。範囲外では対象グリフを返さない |
| in-geometry | path の直線と曲線、rect、circle、入れ子の変換 | 変換後の輪郭と、直接 Painter に与えた等価なパスの描画境界 |
| in-style | 親の塗りの継承、子による上書き、context-fill の入力色2種、半透明の重なり | 固定した内点・外点の RGBA と、重ねる順を反転したときの交点の RGBA |
| in-reference | 同一文書内の use と clipPath を変換と組み合わせる | 展開した図形との一致、クリップの内外の画素、参照元と参照先の変換順 |
| in-gradient | 線形と放射、異なる縦横比、停止点の透明度、gradientTransform | 手計算した色と位置。[ADR 0072](0072-color-gallery-acceptance.md) の color-svg 19・26 は CLI と一覧 PNG まで検査 |
| in-restrictions | 外部参照とスクリプトを含むグリフ | 計測用のリソース読み込み口への要求0件、スクリプトによる図形の変化0件。対照用の可視図形は所定の位置と色 |
| out-page | 空ページ、1グリフ、半透明の2グリフが重なるページ、変換した画像をクリップするページ | 固定版 HarfBuzz の参照 SVG とページ寸法、配置、変換、パス、塗り、画像、クリップ、描画順が一致 |

## データ構造と判定手順

各ケースには機能 ID、ケース ID、入力ファイル、グリフ ID またはページ配置、ppem、前景色、期待する命令または画素とその出典を記録する。
表に列挙した各入力と観測には固定のケース ID と観測名を割り当て、必須組の一覧をテストに置く。
台帳を読むときは、その一覧と台帳にある組の集合を照合する。
同じ機能に複数のケースがあっても、一つを削除すれば欠落を検出する。
たとえば in-gradient に必要な画素が得られなければ、命令の照合だけ成功してもケースは失敗する。

期待値は、合成入力なら仕様から計算した値、実フォントなら採択済み ADR に定めた方法で独立に算出した値、出力なら固定した HarfBuzz の参照ファイルを使う。
テスト入力と一緒に、比較する画素の座標、期待 RGBA の数値、座標系、アルファの表現、計算式または固定版の参照ツールと生成コマンドを保存する。
通常の実行では、検査対象の sofel から期待値を作り直さない。
SVG 出力は XML として解析し、属性の記載順と要素間のインデントを除いて比較する。
属性値、子要素の描画順、変換の合成順は保存する。
失敗時は最初に異なる命令、または座標と期待・実測の RGBA を示す。
OpenType 1.9.1 の SVG テーブル仕様を基準に、参照した文書の版またはリビジョン、節、要求項目ごとの ID と対応するケース ID を台帳に記録する。
必須表で扱わない項目には「対象外」または「未決」と根拠を記録する。
必須表の合格と OpenType 仕様全体に対する網羅状況を別々に表示する。

## 実装しないこと

汎用ブラウザーの SVG エンジン、PDF や GPU 出力の検証、ネットワークからの参照値の自動更新は対象外とする。

## 不変条件

1. 固定した必須組を台帳がすべて含み、各必須ケースの結果は一回だけ現れる。台帳が空、ID が重複、必要な観測が欠落した場合は失敗する。
2. 必須ケースがすべて実行され、宣言した観測のすべてが期待値と一致した場合に限り、検証コマンドは成功する。
3. 同じ固定入力に対するケース ID、結果、実測値はローカルと CI で一致する。実行時刻やローカルのパスは比較値に含めない。

| 境界の入力 | 期待する結果 |
| --- | --- |
| 台帳0件、または必須機能1件だけケース0件 | 欠落を報告して失敗 |
| 指定したグリフの隣のグリフだけ描画 | in-document で失敗 |
| 命令は一致し、指定した1画素だけ不一致 | 座標と両方の値を報告して失敗 |
| 出力ページにグリフ0件 | ページ寸法が一致し、描画命令が空なら out-page の当該ケースは成功 |
| 必須ケース全件一致、対象外の項目あり | 必須表は成功し、対象外は別掲 |

## テスト設計

I1_svg_inventory は台帳からケースを抜く、重複させる、必要な観測を抜く各入力を与え、終了コードと欠落箇所を検査する。
I2_svg_observations は正常な参照値に対し、グリフの選択、回転の順序、色停止点、クリップ、ページの重ね順を一つずつ変え、対応するケースが確実に失敗することを検査する。
同じ検査で、透明画素だけの画像やグレーの代替輪郭が、可視の色を要求するケースに通らないことを確かめる。
I3_svg_reproducibility は固定した参照データとテスト用フォントを使い、同一コミットのローカルと CI の結果を機能 ID とケース ID で突き合わせる。
実装 PR では全必須ケースの結果と対象外・未決の一覧を提示する。

## トレードオフ

小さな合成入力は誤った命令や画素の原因を特定しやすい。
実フォントから画像を生成するケースも残すことで、文書の抽出から CLI や一覧への受け渡しで起こる不具合を検出する。
