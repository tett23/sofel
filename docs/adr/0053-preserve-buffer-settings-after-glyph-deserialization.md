# ADR 0053: C API でグリフ列を読み込んだバッファの設定を再利用する

ステータス: 採択

## 文脈

[ADR 0020](0020-shaping-foundation.md) の C API では、一つのバッファを次のテキストのシェーピングに再利用できる。
呼び出し側が `sofel_buffer_clear` で空の文字バッファに戻したとき、再利用できる設定は、直前のグリフ列をシェーピングで作っても外部から読み込んでも同じであるべきだ。

## 調査した事項

`sofel_buffer_deserialize_glyphs` は、空の文字バッファにグリフ列を読み込み、既存のグリフバッファには読み取った列を追記する。
どちらも結果を `GlyphBuffer::from_parts` に渡す。
この構築子は、再利用用の内部バッファを `Buffer::new()` で作る。
そのため、後から `sofel_buffer_clear` がこの内部バッファを取り出したとき、読み込み前の設定は失われている。

通常の `clear` はフラグ、クラスタレベル、置換用コードポイント、不可視グリフ、未定義グリフ、未定義の異体字セレクタ用グリフの設定を保持する。
一方、乱数状態は 1 に戻す。
グリフ列のパース中にエラーが起きた場合も、現行の C API はパーサーから戻ったグリフ列を格納し、消費したバイト数を返す。

## 実装すること

読み込み後のバッファを `sofel_buffer_clear` で再利用するときは、読み込み前に同じバッファを直接クリアした場合の設定を引き継ぐ。
テキスト形式と JSON 形式の双方で、初回の読み込み、追記、パース途中のエラーに同じ規則を適用する。

## データ構造とアルゴリズム

既存の `GlyphBuffer` が持つ再利用用の内部バッファを使う。
空の文字バッファから読み込むときは、その文字バッファの内部バッファを結果に引き渡す。
グリフ列への追記時は、元のグリフバッファが保持する内部バッファを引き継ぐ。
公開済みの Rust の `GlyphBuffer::from_parts` は、元のバッファを持たずに列から構築する呼び出しに引き続き使えるようにする。

## 実装しないこと

グリフ列の構文、追記の順序、エラーコード、消費したバイト数、通常の `clear` の規則は変更の対象外とする。

## 不変条件

1. 同じ状態のバッファを二つ用意し、一方に任意回数のグリフ列の読み込みに成功してから両方をクリアすると、両方とも長さゼロの文字バッファになり、C API の各設定の取得結果が一致する。
2. グリフ列の読み込みがパースエラーを返した場合も、クリア後の各設定の取得結果は、同じ初期状態から直接クリアした場合と一致する。

| 読み込み前 | 入力 | クリア後の期待値 |
| --- | --- | --- |
| 設定済みの空の文字バッファ | グリフ1件 | 直接クリアした結果と一致 |
| グリフ1件を読み込んだバッファ | さらに1件を追記 | 同上 |
| シェーピング済みのグリフバッファ | グリフ1件を追記 | 同上 |
| 設定済みの空の文字バッファ | 空の入力、先頭で失敗、または1件を読んでから失敗 | 同上 |

## テスト設計

公開 C API のテスト `inv1_clear_after_deserialize` で、保持対象の6設定と乱数状態を既定値以外にし、表の成功例で直接クリアした対照と比較する。
両方で乱数状態が 1 になること、文字を追加して次の処理を始められることも確かめる。
`inv2_clear_after_parse_error` は表のエラー例を両形式で試し、消費バイト数と読み込み済みの列をクリア前に、各設定をクリア後に検査する。
実装前に、設定が初期値に戻る現行経路でテストが失敗することを確かめる。

## トレードオフ

内部バッファを引き渡すため、文字とグリフの両方の状態から読み込み結果を組み立てる処理が要る。
設定を個別に複製する処理が不要になり、通常のクリアと同じ規則を使える。
