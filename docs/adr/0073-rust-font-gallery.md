# ADR 0073: フォントギャラリーの生成器を Rust に移す

ステータス: 採択

## 文脈

[ADR 0069](0069-font-render-gallery.md) の生成器では、入力や描画結果を扱う型をコードから読み取れるようにしたい。
カラー描画の対応状況が変わっても、生成器の移植と対応状況の変更を独立して検証できるようにする。

## 調査した事項

実装コミット 679c9e6 の tools/font-gallery には入力、画素処理、一覧生成を担う Ruby ファイルと、それぞれのテストがある。
シェルの入口は Cargo で sofel-render と sofel-shape をビルドした後、Ruby のテストと生成器を実行する。
リポジトリには Cargo でビルドする開発ツールがあり、同コミットのツリーに deno.json、deno.jsonc、deno.lock はない。

## 実装すること

tools/font-gallery に Cargo でビルドする開発用の Rust バイナリを置く。
シェルの入口、既存のフォント取得と検証、CI のアーティファクト名と保存期間は [ADR 0069](0069-font-render-gallery.md) に従う。
移植後はローカルと CI の入口から Rust のテストと生成器を呼び、Ruby の実装とテストを置き換える。
scripts/tests/test-render-font-gallery.sh の Ruby 直接起動とテスト用の代替コマンドも Rust バイナリに合わせ、通常 CI の失敗経路を検査する。
README に実行手順と依存ツールを記載する。

## データ構造

単字の入力は Unicode スカラー値かグリフ ID かを列挙型で区別する。
フェイス番号、ppem、文字列、言語を見本の構造体にまとめる。
26.6 固定小数点の送りとオフセットは整数画素の位置と区別し、原点と寸法を含む画像の型を定める。
描画成功、登録済みの空グリフ、登録済みのグレー描画を区別し、予期しない失敗はフォント ID とフェイス番号を含むエラーとして返す。
実装時点で解除済みの登録は再導入しない。

## 実装しないこと

レンダラーやシェーパーの仕様変更と、移植を理由とするフォントや文字列の変更は対象外とする。

## 不変条件

1. 同一のフォント、同一の描画器、同一の未対応登録を与えれば、新旧生成器でフェイスの並び、入力、状態、一覧 PNG の寸法とデコード後の RGBA 全画素が一致する。
2. 成功時の HTML は展開先の一覧 PNG を相対パスで参照する。入力検証、描画、保存の失敗時は非ゼロで終了し、今回の成果物として古い画像を公開しない。

| 入力 | 期待する結果 |
| --- | --- |
| 空の台帳 | 失敗 |
| 単一フェイス、複数フェイスの TTC | 条件1の順序と画素で各フェイスを一度ずつ掲載 |
| 未対応の登録と異なる描画結果 | 失敗 |
| 前回成功した後の書き込み失敗 | 条件2に従う |

## テスト設計

I1_rust_gallery_parity は移植直前のコミットの Ruby 生成器と Rust 版を同じ入力で実行し、HTML の見本情報とデコード後の全画素を照合する。
[ADR 0072](0072-color-gallery-acceptance.md) のカラー対応を先に実装した場合は、その変更を含む Ruby 版を比較元にする。
この移行時の比較結果を PR に記録し、移植後の通常 CI は Rust の固定入力テストを実行する。
I2_rust_gallery_publish は旧生成器の失敗ケースを引き継ぎ、異常終了と出力先の状態を検査する。
実装の PR では CI が保存した PNG をローカル生成版と照合し、展開した HTML をオフラインで開く。

## トレードオフ

Deno 上の TypeScript でも入力と結果に型を付けられる。
Rust を選ぶと、すでに描画器に必要な Cargo と Rust ツールチェーンで生成器までビルドでき、PNG の画素と座標の型も同じ言語で扱える。
代わりに、生成器だけを変更したときもコンパイルが必要になる。
