# ADR 0015: C ABI（`sofel-capi`）

ステータス: 採択（未実装）

## 文脈

[ADR 0001](0001-project-goal-and-scope.md) と [ADR 0003](0003-crate-layers.md) は、C言語のAPIを範囲の外とした。
理由は、HarfBuzzやFreeTypeとの互換のABIを持たないことにあった。

sofelはHarfBuzzとFreeTypeを置きかえる汎用のライブラリである。HarfBuzzとFreeTypeの利用者の多くは、C、C++、Python、Swift、Kotlin、Haskell、Goなど、Rust以外の言語から使っている。どの言語からも呼べる共通の口はCの呼び出し規約であり、Rustの公開のAPIだけでは置きかえの相手の大半に届かない。

最初の利用者になる予定のGolemも、そうした例の1つである。Golemは組版の道具である。
GolemはHaskellで書かれ、PDFの出力でフォントを扱う。
いまは、HarfBuzz 14.6.0とFreeType 2.14.3をソースのまま同梱して静的にリンクし、15ほどの関数を持つ薄いCの層（`modules/golem-font/cbits/golem/golem_font.{h,c}`）を、HaskellのCApiのFFIで呼んでいる。
HaskellからRustのライブラリを呼ぶには、Cの呼び出し規約の関数が要る。

Golemの層は、次の性質に依存している。

- フォントをバイト列から開く。パスは渡さない。
- 結果はすべてフォントの単位の整数（HarfBuzzの拡大縮小を `unitsPerEm` にしている）。
- x86-64、aarch64、wasm32-wasiで、同じ出力になる（決定性）。
- FreeTypeの `FT_Face` は可変なので、Golemは顔ごとにミューテックスを持っている。HarfBuzzのオブジェクトは読み取りだけで共有している。
- wasm32-wasiでは、FreeTypeの `setjmp` のために例外処理の提案（`-mllvm -wasm-enable-sjlj`）でビルドし、libc++とlibc++abiをリンクしている。このため、golem-fontに依存するHaskellのパッケージはTemplate Haskellを使えない。

sofelの値は不変で、`Send` と `Sync` を満たす（[ADR 0003](0003-crate-layers.md)）。
Cの層からもこの性質を保てば、Golemのミューテックスは要らなくなる。
純粋なRustなので、wasmで例外処理の提案も、C++の実行時ライブラリも要らない。

## 実装すること

### 範囲の変更

- [ADR 0001](0001-project-goal-and-scope.md) の「実装しないこと」のうち、C言語のAPIを範囲に入れる。ただし、sofel独自のABIとする。HarfBuzzやFreeTypeとの互換のABI（`hb_*`、`FT_*` の名前と構造体）は、引き続き扱わない。
- [ADR 0003](0003-crate-layers.md) のクレートの表に `sofel-capi` を足す。依存は `sofel-cli` と同じく、ライブラリのクレートのすべてとする（`scripts/deps.txt` に `sofel-capi *` を足す）。
- [ADR 0003](0003-crate-layers.md) の `#![forbid(unsafe_code)]` は、ライブラリのクレートについての決まりである。`sofel-capi` は、Cから渡されたポインタを扱うために `unsafe` を使う。ほかのクレートでは、引き続き禁止する。
- 実装のプルリクエストで、[ADR 0001](0001-project-goal-and-scope.md) と [ADR 0003](0003-crate-layers.md) のステータスを「C言語のAPIは [ADR 0015](0015-c-abi.md)」と改め、`docs/specifications.md` の「C言語のAPIは扱わない」を改める。

### クレート

- `crates/sofel-capi` を作る。`crate-type = ["staticlib", "cdylib", "rlib"]` とする。
- `std` を使ってよい（`sofel-cli` と同じく、ライブラリではなく境界の層であるため）。ただし、ファイルとスレッドと時刻は使わない。
- `unsafe` は、ポインタからスライスや参照を作る箇所だけに置く。各 `unsafe` に、満たすべき前提を `// SAFETY:` で書く。境界の外側の処理（引数の検査のあと）は、`unsafe` のない関数に分ける。
- ヘッダは手で書き、`crates/sofel-capi/include/sofel.h` に置く。生成の道具（cbindgenなど）には依存しない（[ADR 0001](0001-project-goal-and-scope.md) の自作の方針）。ヘッダと実装の食い違いは、下のテストで見つける。

### 呼び出しの約束

- 名前は `sofel_` で始める。型は `sofel_font_t` のような不透明な構造体へのポインタと、固定の幅の整数（`<stdint.h>`）だけを使う。
- **フォント**：`sofel_font_t *sofel_font_create(const uint8_t *data, size_t len, uint32_t index, int32_t *error)` で作り、`sofel_font_destroy` で捨てる。データは複製しない。呼び出し側は、フォントを捨てるまでデータを生かしておく（HarfBuzzの `HB_MEMORY_MODE_READONLY` と同じ）。フォントの値は不変で、作ったあとは複数のスレッドから同時に呼んでよい。
- **作業領域**：輪郭の `Scratch`、ラスタライザ、シェーピングのバッファなど、呼び出し側が持つ値（[ADR 0003](0003-crate-layers.md)）は、それぞれ `sofel_*_create` と `sofel_*_destroy` を持つ不透明な型とする。スレッドの間で共有しない（スレッドごとに作る）ことをヘッダに書く。
- **誤り**：誤りうる関数は `int32_t` を返し、0を成功、負の値を誤りとする。誤りの番号は `sofel.h` に列挙し、`sofel_error_string(int32_t)` で英語の短い説明を返す。結果は出力の引数に書く。
- **可変長の出力**：グリフの列や名前の文字列は、呼び出し側の配列に書く。配列が足りなければ、要る長さを返して何も書かない（`snprintf` と同じ形）。サブセット化の出力のように大きなものは、sofelが確保して `sofel_bytes_t`（ポインタと長さ）で返し、`sofel_bytes_destroy` で解放する。
- **NULL**：ポインタの引数がNULLなら、誤りを返す。panicしない。ライブラリのクレートはpanicしないこと（[ADR 0007](0007-sfnt-read-foundation.md) のlint）を前提とし、`sofel-capi` も `extern "C"` の関数の中でpanicしない。万一のpanicは、Rustの `extern "C"` の規則によりプロセスを止める（巻き戻しを境界の外へ出さない）。
- **版**：`SOFEL_VERSION_MAJOR` などのマクロと `sofel_version()` を持つ。1.0.0までは、ABIの互換を約束しない。

### 範囲

- C ABIは、ライブラリのクレートの公開のAPIと同じ機能を持つ。Rustから使える機能は、Cからも使えるようにする。Rustの型（トレイト、イテレータ、借用）は、不透明な型、関数ポインタと `void *user`、呼び出し側の配列に写す。
- 1つの関数は1つの問い合わせに対応させ、HarfBuzzやFreeTypeの利用者が対応を探しやすいよう、ヘッダの各関数の説明に、相当するHarfBuzzとFreeTypeの関数の名前を書く。

### 最初の関数

この ADR の実装では、いま実装済みの機能を公開する。

| 関数 | 中身 |
|---|---|
| `sofel_font_create`、`sofel_font_destroy` | `Font::new` |
| `sofel_font_units_per_em`、`sofel_font_num_glyphs` | 同名の関数 |
| `sofel_font_nominal_glyph`、`sofel_font_variation_glyph` | 文字からグリフ |
| `sofel_font_h_advance` | `Font::advance` |
| `sofel_font_table` | 表のバイト列（フォントのデータの中を指すポインタと長さ。複製しない） |
| `sofel_outline_*` | `Scratch` の作成と破棄、輪郭の命令をCの関数ポインタ（`move_to` などと `void *user`）で受け取る `sofel_outline_draw` |
| `sofel_render_glyph` | `sofel_cli::glyph::render` 相当。画像は呼び出し側の配列に書く |
| `sofel_validate` | 検証の誤りを、Cの関数ポインタで1件ずつ渡す |

### 機能を足すときの決まり

- この ADR より後の ADR がライブラリに公開の機能を足すときは、同じプルリクエストで `sofel-capi` の関数とヘッダとCのテストも足す。各 ADR は、足す関数の名前と形を「実装すること」に書く。
- Rustの公開のAPIとC ABIの対応は、`scripts/` の検査で機械的に確かめる。ライブラリのクレートの公開の関数の一覧（`cargo doc` のJSONの出力、またはrustdocの索引）と、ヘッダの説明に書いた対応の一覧を照合し、対応の無い公開の関数があれば失敗させる。意図して公開しない関数は、理由を添えて除外の一覧に書く。
- 利用者ごとの都合の関数は作らない。例えばGolemの `golem_font.h` の関数は、sofelの関数の組み合わせで置きかえる。HarfBuzzとFreeTypeを混ぜた現在の形（送り幅をFreeTypeから、原点をHarfBuzzから取るなど）は写さず、sofelの方針（[ADR 0010](0010-font-foundation.md)：メトリクスはHarfBuzzに従う。FreeTypeの値は `ft_` の付いた関数で別に引く）に従う。

### wasm

- `wasm32-wasip1` の静的ライブラリをビルドし、wasi-sdkのclangでCのプログラムとリンクできることを確かめる（[ADR 0013](0013-benchmark-harness.md) の `bench/wasi-sdk.lock` を使う）。例外処理の提案もC++の実行時ライブラリも要らないことを、リンクの引数で確かめる。
- `wasm32-unknown-unknown` は、Cのプログラムとリンクする相手が無いため、ビルドだけを確かめる。

## 実装しないこと

- HarfBuzzやFreeTypeと互換のABI（`hb_*`、`FT_*` の名前と構造体の配置）。下の「後回しにしたもの」で、別のADRとして判断する。
- Haskellの束縛（Golemの側で書く）と、ほかの言語の束縛（wasm-bindgen、Python、Node.jsなど）。
- 動的ライブラリの版の管理（soname）とパッケージ（pkg-config、CMakeの設定）。必要になったら別に判断する。
- 内部で作業領域を確保して隠すAPI（呼び出しごとに `Scratch` を作るなど）。呼び出し側が作業領域を持つ形だけとする。

## 後回しにしたもの

この ADR の実装が済んだら、次のADRを起こす。

- **HarfBuzzとFreeTypeの互換の層**：既存のプログラムを作りなおさずに置きかえるための、`hb_*` と `FT_*` の名前の関数の層（`libharfbuzz.so` と `libfreetype.so` の差しかえ）。どこまでの関数を写すか、可変のオブジェクト（`FT_Face`、`hb_buffer_t`）をsofelの不変の値にどう写すか、ABIの版をどう名乗るかを決める。sofel独自のC ABIの上に作り、sofelのライブラリには入れない。
- **言語の束縛の生成のための記述**：ヘッダから他の言語の束縛を作る道具（Pythonのcffi、SwiftのモジュールのマップなどへのC ABIの記述）。ヘッダの書式の決まりだけを決め、束縛そのものは作らない。

## テスト設計

実装のまえに、次のテストを書いて失敗させる。

- **Cのテスト**：`crates/sofel-capi/tests/c/` にCのプログラムを置き、`build.rs` を持たない小さなシェルのスクリプト（`scripts/test-capi.sh`）で、静的ライブラリとリンクして走らせる。全関数を1回以上呼び、[ADR 0007](0007-sfnt-read-foundation.md) の組み立て方で作ったフォント（バイト列をヘッダに埋めこむ）で、Rustの関数と同じ結果になることを確かめる。
- **ヘッダと実装の一致**：Cのテストを `-Wall -Werror -Wmissing-prototypes` でコンパイルする。ヘッダの宣言と実装の型が食い違えばリンクか実行で落ちるよう、全関数のポインタを型つきの変数に代入する。加えて、静的ライブラリの公開シンボルの一覧（`nm`）と、ヘッダの関数の一覧が一致することを、スクリプトで確かめる。
- **誤り**：NULLのポインタ、範囲外のグリフ、足りない配列（要る長さが返り、配列が書きかわらないこと）、壊れたフォントで、決めた誤りの番号が返ることを確かめる。
- **スレッド**：1つのフォントを4つのスレッド（pthread）から同時に引き、結果が1つのスレッドで引いたときと同じことを確かめる。ThreadSanitizer（`-fsanitize=thread`）のビルドで、ネイティブのLinuxで走らせる。
- **メモリ**：AddressSanitizerのビルドで、作成と破棄の対、`sofel_bytes_destroy`、範囲外の読み書きが無いことを確かめる。
- **wasm**：同じCのテストを、wasi-sdkで `wasm32-wasip1` にビルドしてwasmtimeで走らせる。リンクの引数に `-lsetjmp`、`-lc++`、`-lc++abi` が無いことを確かめる。
- **Rustの公開のAPIとの対応**：上の照合のスクリプトを `scripts/tests/` のテストで確かめる。わざと対応を消した一時のヘッダで失敗することを確かめる。
- **`unsafe` の範囲**：`sofel-capi` 以外のクレートが `#![forbid(unsafe_code)]` のままであることを、`scripts/check-deps.sh` の検査に足す。
- CIの `rust` ジョブに、Cのテストのネイティブ版を、`bench` と同じジョブの構成でwasm版を足す。

## トレードオフ

- `unsafe` を使うクレートが1つ増える。境界の層に閉じこめ、ライブラリのクレートの禁止は保つ。
- ヘッダを手で書くため、関数を足すたびにヘッダも直す手間がある。シンボルの一覧の照合で、漏れは機械的に見つける。
- データを複製しないため、呼び出し側がデータを生かしておく責任を負う。Golemの現在の層はデータを複製しているが、Haskellの `ByteString` を固定して渡せば、複製と確保を省ける。複製を望む利用者は、自分で複製してから渡せばよい。
- 作業領域を呼び出し側に持たせるため、関数の数が増える。代わりに、確保の回数とスレッドの扱いが利用者に見え、隠れたロックも要らない。
- ABIの互換を1.0.0まで約束しないため、Golemはsofelの版を固定して同梱する必要がある。Golemはいまも版を固定して同梱しているので、運用は変わらない。
- Golemを置きかえると、HarfBuzzとFreeTypeの版の更新と同じく、出力が変わりうる。メトリクスはHarfBuzzに揃える方針なので、送り幅と箱をFreeTypeから取っている箇所は値が変わる可能性がある（例：vmtxの無いフォントの縦の送り幅、pp1.xのずらし）。Golemの側で、置きかえの前後の出力を比べる必要がある。
