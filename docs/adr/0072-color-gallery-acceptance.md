# ADR 0072: OT-SVG の矩形と円を描き、カラー見本8グリフを検証する

ステータス: 採択

## 文脈

[ADR 0066](0066-color-glyph-pixels.md) のカラー描画を、[ADR 0069](0069-font-render-gallery.md) の実フォントでも検証する。
単字だけが描けても、隣に並ぶ文字列で同じ機能が働くとは限らない。
そこで単字と文字列の双方を受け入れ条件に含める。

## 調査した事項

既定座標でギャラリーの入力を `sofel-shape`、`sofel-paint`、`sofel-render --color` に渡した。
最初の3フォントでは単字19と、文字列 `simple_linear` が合字になった26が空だった。
可変 COLR フォントでは単字92と文字列 U+F0502 U+F0503 の92、93がいずれもグレーの PGM になった。
下表のグラデーションとクリップは塗り命令から、SVG の図形と属性はフォント内の非圧縮 SVG 文書から確認した。

sbix の2グリフの PNG はどちらも128×128画素である。
ギャラリー実装（679c9e6）の単字欄の上限は幅106画素、高さ99画素で、どちらも収まらない。

## 実装すること

OT-SVG の対象グリフの要素を選び、矩形（rect）と円（circle）を輪郭に変換する。
同じ文書の defs 内にあるグラデーションを fill の url(#id) から引き、停止点の色と stop-opacity を使って文書順に塗り重ねる。
gradientUnits を省略したときは塗る図形ごとの境界ボックスを使う。
その座標系に gradientTransform を適用し、図形を囲むグループの transform を描画面にも反映する。

sbix の登録を外す際には単字と文字列を等倍で置けるように欄を広げ、ラベルと重ならない位置に配置する。

### 実フォントの受け入れ条件

全件でフェイス0、既定のパレットと軸座標を使う。
番号はフォント内のグリフ ID である。

| フォント | ppem | ID | 合格とする描画 |
| --- | ---: | ---: | --- |
| color-cff | 48 | 19 | CFF 輪郭28・29でクリップした線形と放射のグラデーションが、変換と半透明の重なりを含めて条件1に一致 |
| color-cff | 48 | 26 | 輪郭28を使う2本の線形グラデーションが、それぞれの変換を適用して条件1に一致 |
| color-sbix | 109 | 19 | グリフ19のストライク内の PNG を復号し、条件2に一致 |
| color-sbix | 109 | 26 | グリフ26自身の PNG を復号し、条件2に一致 |
| color-svg | 48 | 19 | 2本の矩形の上に放射グラデーションの円を描き、中心、円周近く、図形外の色とアルファが条件3に一致 |
| color-svg | 48 | 26 | 横長の矩形は左から右、縦長の矩形は上から下に金色から赤へ変わり、交点を含め条件3に一致 |
| hb-variable-colr | 48 | 92 | 緑・白・赤の線形グラデーションが、クリップと延長方法を含め条件1に一致 |
| hb-variable-colr | 48 | 93 | 緑・白・赤の放射グラデーションが、クリップと延長方法を含め条件1に一致 |

## 実装しないこと

SVG のスクリプト実行、外部リソースの取得、ギャラリーのフォント追加は対象外とする。

## 不変条件

1. COLRv1 は、同じパレット、座標、原点、寸法で固定版 HarfBuzz raster と比較し、[ADR 0066](0066-color-glyph-pixels.md) のチャンネル順にそろえた全画素が一致する。
2. sbix は PNG 対応の固定版 FreeType が対象グリフのロードに成功し、ストライク、原点、寸法、乗算済み BGRA の全画素が一致する。
3. SVG の矩形と円は同じ図形を明示したパスで Painter に直接渡した場合と描画境界が一致する。固定した内点と外点の RGBA は、SVG の変換、色停止点、アルファ、描画順から独立に求めた8ビットの期待値に一致する。
4. フォントの未対応登録を外せるのは、そのフォントの全対象 ID が条件1〜3の該当条件を満たし、単字とシェーピング後の文字列の双方が条件5を満たす場合だけとする。
5. ローカル生成と CI から取得した一覧 PNG の当該欄は、単字のカラー出力および文字列を所定位置で合成した期待画像と、デコード後の画素が一致する。ラベルと背景を除いた単字の領域と文字列の領域のそれぞれに、アルファが正で RGB の少なくとも2成分が異なる画素を含む。HTML の状態は「描画済み」となり、一覧 PNG から未対応の注記が消える。

| 境界の入力 | 期待する結果 |
| --- | --- |
| 片方の ID だけ合格 | フォント単位の登録解除は不可。既知症状が変化したケースを成功扱いしない |
| 両 ID が有彩色だが円が欠落、または2本の矩形が同方向 | 条件3で失敗 |
| CLI は合格、一覧の文字列だけグレー | 条件5で失敗 |
| 両 ID と一覧が合格 | 当該フォントの登録のみ外し、正常なカラー描画を以後も検査 |

## テスト設計

I1_colr と I2_sbix は表の各 ID を独立したケースにし、参照実装がエラーや空画像を返した比較は失敗とする。
I3_svg は変換前の図形座標で、横棒だけ、縦棒だけ、交点、円の中心と外周付近、背景の点を選び、画素中心へ写した位置と期待 RGBA をケースに記録する。
グループ変換前の座標では、横棒の (2, 5) と (8, 5)、縦棒の (5, 2) と (5, 8)、交点 (5, 5)、円内の (6.7, 5.6)、図形外の (2, 2) をアンカーにする。
各アンカーに最も近い出力画素の中心を逆変換して期待色を求める。
実装の SVG パーサーを通さず、横棒の勾配位置を (x−1)/8、縦棒を (y−1)/8、円を中心 (5, 5) からの距離を2で割った値として計算する。
実フォントに記された色停止点と不透明度から塗りを求め、横棒、縦棒、19だけはその上の円の順に合成する。
外点の期待アルファは0である。
図形境界のアンチエイリアスは等価なパスとの比較で調べる。
I4_registration と I5_gallery は未対応登録を外す変更と同じ PR で実行する。
ID 92 が単字と文字列の両方に現れる箇所も個別に照合し、文字列側の93の欠落を検出する。
正常ケースになったフォントが再び空やグレーに戻ればテストを失敗させる。

## トレードオフ

実フォントで描画から一覧への掲載までを検査すると、塗り命令の列挙だけでは分からない退行を見つけられる。
この8グリフが通っても、他の軸座標や SVG の全要素の対応範囲は広がらない。
