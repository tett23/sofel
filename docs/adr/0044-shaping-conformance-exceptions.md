# ADR 0044: シェーピングの適合テストで dfont と破損したレイアウト表の既知の差を認める

ステータス: 採択

## 文脈

[ADR 0020](0020-shaping-foundation.md) は、HarfBuzz とのシェーピング結果の差に理由を付けて追跡する。
固定した HarfBuzz 15.1.0 のテストには、[ADR 0020](0020-shaping-foundation.md) が定めた分類では説明できない入力が二種類ある。
一つは Mac のリソースフォークに格納されたフォント（dfont）であり、[ADR 0007](0007-sfnt-read-foundation.md) が読み取りを後の段階に送っている。
もう一つは、破損したレイアウト表の有効な部分を sofel が読む一方、HarfBuzz のサニタイザが表全体を捨てる入力である。

## 実装すること

次の既知の差を [ADR 0020](0020-shaping-foundation.md) の完了判定で許す。
3つの適合テストは、それぞれ期待失敗一覧に入力の識別子と分類を記録する。
以下の識別子は HarfBuzz 15.1.0 のテストデータに対するものである。

| 分類 | テスト | 許す入力 |
|---|---|---|
| `dfont` | シェーピング | `in-house/collections.tests:1` |
| `sanitize` | シェーピング | `in-house/harfbust.tests:4` |
| `sanitize` | レイアウトの選択（`--layout-map`） | 下記の3フォントのフェイス0 |
| `sanitize` | 無作為な文字列のシェーピング（`--shape-random`） | 下記の各フェイスと文字体系の組 |

3フォントはいずれも `test/shape/data/in-house/fonts/` にある。
`HarfBust.ttf` の文字体系は `Latn`、`36f8e7f3b4f54efaa6bfd8225893022dc0041915.ttf` と `ecc344a5fa31c4d69350231bb3b96cc693646089.ttf` は `Arab` である。

## 実装しないこと

dfont の読み取りと HarfBuzz のサニタイザの移植はこの変更の範囲外とする。
[ADR 0020](0020-shaping-foundation.md) のほかの完了条件は引き続き適用する。

## 不変条件

1. `dfont` と `sanitize` で許す項目は、上表の入力とテストと分類の組に含まれる。
2. 一覧にある項目が参照出力と一致したとき、適合テストは失敗し、一覧からの削除を促す。
3. 一覧にない項目が参照出力と異なるとき、適合テストは失敗する。

| 境界の入力 | 期待する結果 |
|---|---|
| 一覧が空で全件が一致 | 成功 |
| 一覧にある1件だけが指定の理由で不一致 | 成功 |
| その1件が一致 | 失敗 |
| 既知のフェイスに別の文字体系を1件追加して `sanitize` に分類 | 失敗 |
| 一覧の外で1件不一致 | 失敗 |

## テスト設計

テスト名に不変条件の番号を入れる。
I1 は3つの期待失敗一覧を読み、分類と識別子の組を上表と照合する。
許容した項目が減った場合も通ること、別のフェイス、文字体系、行番号または分類に変えると失敗することを確かめる。
I2 と I3 は、一致と不一致を1件ずつ作り、期待失敗を判定する既存の関数に通して確かめる。
固定したテストデータによる3つの適合テストも走らせる。

## トレードオフ

この判断により、古い形式の読み取りと破損した表の扱いを後の段階で決められる。
既知の差が解消するまでは、上表の入力で HarfBuzz と同じ結果を必要とする用途に制約が残る。
許す範囲を識別子で限定するため、固定したテストデータを更新して行番号や入力が変わったときは対応を見直す必要がある。
