# ADR 0039: 生成表の再現検査を適合テストと並列に実行する

ステータス: 採択

## 文脈

[ADR 0033](0033-ci-latency-and-ligature-iteration.md) の評価基準はworkflow完了時間である。[追加フォント導入時のCI](https://github.com/tett23/sofel/actions/runs/42898972555) ではmacOSの適合ジョブが487秒で最後に完了した。Linuxの適合ジョブは344秒、benchは245秒だった。macOSでUnicode表、言語タグ表、音節機械の生成器を検査し再生成する6ステップは合計31秒で、その終了後に参照ツールのビルドを開始した。

## 実装すること

生成器のテストと再生成を専用のmatrixジョブに移す。LinuxとmacOSの各ジョブは固定されたHarfBuzzとUCDを取得し、各生成器のfmt、テストと再生成、追跡ファイルとの差分検査を順に行う。適合ジョブはコミットに含まれる表を使う。別々のcheckoutで実行するため、再生成とコンパイルが同じファイルにアクセスしない。

[ADR 0032](0032-documentation-only-ci.md) と [ADR 0034](0034-ci-document-input-classification.md) の文書分類を両方のジョブに適用し、最終判定に生成器の結果を加える。適合ジョブは自身のUnicode適合試験にも使うUCDを引き続き取得する。

## 実装しないこと

生成表のアルゴリズム変更と比較ケースの削減は対象外とする。

## 不変条件

1. 通常CIでは両OSで3生成器の検査をすべて実行し、生成器ジョブが成功した場合だけ最終判定を通す。
2. 文書だけのCIでは生成器ジョブがskippedの場合だけ最終判定を通す。文書と変更禁止ファイルの検査は必須とする。

| 入力 | 生成器の結果 | ほかの必須条件を満たした場合の最終判定 |
| --- | --- | --- |
| 通常 | success | 成功 |
| 通常 | skipped、failure、cancelled、空 | 失敗 |
| 文書だけ | skipped | 成功 |
| 文書だけ | success、failure、cancelled、空 | 失敗 |

## テスト設計

I01とI02の各行を最終判定スクリプトへ渡す回帰テストを先に書く。workflowの変更前後で両OS、生成器の実行コマンドとデータ取得先を照合する。CIでの効果は、採択後にworkflow開始から最終ジョブ終了までと各ジョブの待ち時間で測る。

## トレードオフ

追加のrunnerをOSごとに1台使う。runnerが空いていれば生成器の検査と適合ジョブが重なる。待ちやキャッシュ取得の増加によって効果が小さくなる可能性がある。観測した31秒は移動対象ステップの実行時間で、変更後の短縮量は未測定である。
