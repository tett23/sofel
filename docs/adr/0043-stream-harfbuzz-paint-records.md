# ADR 0043: HarfBuzzの塗りの参照出力をグリフごとに比較する

ステータス: 採択（未実装）

## 文脈

[ADR 0023](0023-color-glyphs.md) の `harfbuzz_color` は、HarfBuzzの `--paint`、`--color`、`--extents` を使い、カラーグリフを持つ92フォントと24の既知の塗りを比較する。
シェーピングの結果を集約した後の2並列の適合テストのピークRSSは1,470,320 KiBで、このうち `harfbuzz_color` が1,392,784 KiBを占めた。

固定コーパスの2フォントでは、`--paint` の標準出力がそれぞれ403,411,768 byteで、その全量を読み込んだ `Vec` の容量は536,870,912 byteだった。
その後で663個の塗りの本文を別の文字列にコピーし、合計403,400,876 byteを保持した。
一番長いグリフの本文は4,349,994 byteだった。

## 実装すること

`--paint` の参照出力をパイプで読み、フェイス、パレット、ppem、グリフの組ごとに一つの塗りを比較する。
既知の24件では、同じ読取処理で指示した塗りを探し、HarfBuzzが固定の期待テキストを再現することも確かめる。
比較項目の識別子、順序、件数と判定、`SOFEL_FAILED_ITEMS` の失敗詳細を保つ。

## データ構造とアルゴリズム

`face INDEX` から `end` までの間、現在のフェイスの番号を一つ保持する。
`paint PALETTE PPEM GLYPH COUNT` の後の `COUNT` 行を一つの文字列に読み、本文の改行を含めて比較に渡す。
ヘッダーと本文の文字列は次のグリフでも使い回す。本文全体をテキストで比べるため、必要な領域は最大の一つの本文に依存する。

各コマンドの比較結果はそのコマンドに閉じた値に集める。すべての出力を処理した後に子プロセスの終了を確かめ、成功した呼び出しの結果を加える。
途中で構文エラーを見つけた場合も出力を排出して終了状態を得る。
全フォントの比較では、参照プロセスの非ゼロ終了を従来どおり除外する。既知の24件は参照プロセスの成功を必須とする。

## 実装しないこと

`--color` と `--extents` の形式、HarfBuzzの参照CLI、塗りのアルゴリズム、期待する失敗の一覧と並列数の変更は対象外である。

## 不変条件

1. 成功した妥当な入力では、読み取りの区切りによらず、元のフェイス順、パレット、ppem、グリフ、改行を含む本文を一件ずつ同じ順で渡す。
2. `COUNT` が0なら本文は空となる。宣言した本文の欠落、ヘッダーの不正、フェイスの外の塗り、終端のないフェイスは成功した参照出力として受け付けない。
3. 塗りの読取りが一件完了した時点でその塗りを比較でき、それ以前の塗りの本文を次のグリフのために保持しない。
4. 参照コマンドが非ゼロで終了した場合、途中まで得た結果を取り込まない。終了状態0の構文エラーとパイプの読み取り失敗は失敗にする。

| 入力 | 結果 |
| --- | --- |
| 空、または塗りの無い完結したフェイス | 塗りは0件 |
| 本文の行数が0または1 | 指定しただけの本文 |
| 二つのフェイスに複数のグリフ | 元の順序で一件ずつ比較 |
| 宣言より本文が短い、`end` がない | 成功した参照ならエラー |
| 部分出力のあと非ゼロ終了 | 呼び出し単位で破棄 |

## テスト設計

I1は読み取りを1 byteなどに区切った入力を旧パーサーの結果と比べる。I2は空、行数不足、不正な数、フェイス外の塗りと終端欠落で確かめる。
I3は次の読み取りが失敗する前に最初のグリフの比較を呼んだかを調べる。I4は有効・不正な部分出力のあとで非ゼロ終了する子プロセス、成功する子プロセスで調べる。
実データでは全比較件数と失敗詳細ファイルを照合し、対象単体と名前順2並列の全体を複数回実行して時間・RSSを比べる。

## トレードオフ

一つの本文が大きいと、その最大本文を比較する分の領域が要る。参照は読み取り側の比較中にパイプの空きを待ちうる。
変更後の全体RSSには同時実行する他のテストも含まれる。
