# ADR 0037: ラスタ適合テストをグリフ単位で逐次比較する

ステータス: 採択

## 文脈

[ADR 0033](0033-ci-latency-and-ligature-iteration.md) の2並列を維持しながら、適合テストのメモリ使用量を削減する。
`raster.rs` はFreeTypeの出力全文、全フェイスと全グリフに分けた文字列、全ケースのIDと比較結果を保持する。
最後の期待する失敗の判定では、実行した全IDをさらに集合へ複製する。
参照出力と成功したケースの全量を同時に保持する必要はない。

## データ構造とアルゴリズム

FreeTypeの標準出力を `BufRead` で読み、現在のフェイス、宣言されたグリフ数、現在のグリフとその行だけを保持する。
次のグリフまたはフェイス末尾で比較を済ませ、そのグリフの参照行を解放する。
`error` の数値を無視する既存の正規化は保つ。
固定版の `ft-dump` が出す昇順のフェイスとグリフを受け付け、途中で切れた出力や重複を失敗にする。
既存の全文パーサーは他の利用者のために残す。

比較結果は件数を数え、問題があったケースとその詳細だけを保持する。
期待する失敗に該当したIDだけを別の集合に記録し、最後に一覧との差集合を未実行として報告する。
成功した全ケースのIDを集める集合は作らない。
ただし、参照プロセスが非ゼロで終了した場合に既存と同じくその呼び出しを除外できるよう、結果は呼び出し単位で保留する。
保留するのは件数、問題と照合済みの期待する失敗のIDだけであり、成功した一般ケースのIDは保持しない。

通常の `Vec` と標準入出力を使う。
入力の順序と消費時点を変えることで保持量を減らし、アロケータやmmap、新しいunsafeは導入しない。

## 実装すること

既存と同じフォント、全グリフ、12・24・48 ppem、FreeTypeの参照を使う。
輪郭を扱えないフェイスとFreeTypeが開けなかった入力の既存の扱いは保つ。
参照プロセスの終了を必ず待ち、読み取りエラーは失敗にする。
固定版のFreeType参照は開けた入力に少なくとも一つのフェイスを出力するため、空出力のまま終了状態0になった呼び出しも失敗にする。
構文エラー時はパイプを読み捨ててから終了を待ち、書き込み側をパイプ容量のために待たせたままにしない。

期待する失敗の判定、未実行と予期しない成功の検出、差分の詳細、問題一覧の保存先は保つ。
CIの並列数とライブラリ本体は変更しない。

## 実装しないこと

- グリフやフォントを間引くこと。
- ラスタライザや輪郭のアルゴリズムを変えること。
- outlineなど他の適合テストを同時に逐次化すること。
- 既存の期待する失敗の一覧を変更すること。

## 不変条件

1. 同じ妥当な参照出力を全文で解析した場合と逐次解析した場合で、フェイス番号、グリフ番号、正規化済みの行が一致する。
2. 空、正常終了した空フェイス、一つのグリフ、複数フェイスを区別し、宣言したグリフの不足、重複、末尾の欠落を成功にしない。
3. 読み取り幅によらず結果が一致し、一つのグリフを比較するまでに後続の全グリフを保持しない。
4. 同じケース列に対して、既存の `expect::judge` と問題の種類、ID、順序が一致する。参照呼び出しが失敗した場合はその呼び出しの比較件数と判定を加えない。
5. 既存コーパスのケース件数、失敗件数と期待する失敗の判定が変更前後で一致する。

| 境界の入力 | 結果 |
| --- | --- |
| 空の出力 | 解析結果は0フェイス。呼び出しが終了状態0なら失敗、非ゼロなら既存と同じく除外 |
| グリフ数0のフェイス | グリフの比較0件 |
| グリフ数1、グリフ数2 | 宣言した全グリフを一度ずつ比較 |
| フェイスのエラー | 当該フェイスを比較しない |
| グリフのエラー | 数値コードを除いた `error` を比較 |
| 改行をまたぐ1バイトの読み取り | 通常幅と同じ結果 |
| グリフの重複、番号の欠落、`end` の欠落 | 構文エラー |
| 途中の読み取りエラー | テスト失敗 |
| 期待する失敗が成功、一覧のIDが未実行 | 既存と同じ問題を報告 |
| 一般の成功ケースだけが多数ある | 成功ケースのIDを保持しない |

## テスト設計

不変条件1から4のテストを先に書いて失敗させる。
小さな参照テキストを既存パーサーと比較し、1バイトと通常幅のreaderでも照合する。
途中の読み取りエラーを返すreaderと、グリフを渡した時点で読んだ位置を確かめるreaderを使う。
期待する失敗の判定は、成功、回帰、予期しない成功、未実行と参照失敗の組み合わせを既存の判定と比較する。

変更前後の同じ既存テストをビルド済み実行ファイルで走らせ、件数、実時間、子孫プロセスの合計RSSを比較する。
計測中は他の担当のビルドを止める。
全体の2並列とCIのworkflow完了時間への効果は、単体の結果から推測しない。
変更後のCIは採択後に確認する。

## トレードオフ

プロセスの出力を読みながら比較するため、参照側はパイプが満ちると待つ。
一方、参照全文のコピーと、成功した全ケースの文字列の保持を省ける。
ラスタライザ自身の作業領域はこの変更では減らない。
同じ53万2,833件を比較したローカルの単体測定では、子孫プロセスの合計RSSの最大観測値が806,512 KiBから17,616 KiBに減った。
実時間は35.96秒と26.59秒で、各1回の測定である。
測定条件と限界は [計測記録](../benchmarks/2026-11-11-streamed-raster-reference.md) に記す。
