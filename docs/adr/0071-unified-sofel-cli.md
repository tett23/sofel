# ADR 0071: sofel コマンドから画像の書き出しとフォントの調査を行う

ステータス: 採択

## 文脈

作業中に文字の形を確かめるときは、まず画像を見て、必要に応じてグリフ番号や描画命令を調べたい。
そのたびに実行ファイルの名前や引数の順序を思い出さずに済むよう、入口を `sofel` にそろえる。

## 調査した事項

[sofel-cli の五つの実行ファイル](../../crates/sofel-cli/src/bin)は、それぞれ OS の引数列と出力先を同じクレートの `run` 関数に渡す。
`sofel-subset` は標準入力も渡す。
[render](../../crates/sofel-cli/src/render.rs) は一つのグリフを PGM または PAM として標準出力に書き、[paint](../../crates/sofel-cli/src/paint.rs) はカラーグリフの描画命令をテキストで書く。
手元の Roboto-Regular.ttf に既存の render を使い、48 ppem で U+0041 のアウトラインから幅31、高さ35画素の PGM が得られた。
[ADR 0069](0069-font-render-gallery.md) は、固定したフォントの見本を一括生成する提案である。

## 実装すること

`sofel-cli` に実行ファイル `sofel` を追加する。
最初の引数で操作を選び、既存の処理を同じプロセスで呼ぶ。
従来の五つの実行ファイルも残す。

| 操作 | 用途 | ヘルプに載せる使用例 |
| --- | --- | --- |
| render | 任意の文字列を一枚の画像に書き出す | `sofel render --ppem 48 --text "office & affix" font.ttf > sample.pgm` |
| shape | 文字列に対応するグリフ番号と配置を見る | `sofel shape -O json --no-glyph-names font.ttf office` |
| paint | カラーグリフの描画命令を見る | `sofel paint --glyph 26 color.ttf` |
| validate | フォントの検査結果を読む | `sofel validate --json font.ttf` |
| subset | 指定した文字を残したフォントを作る | `sofel subset --output-file=small.ttf font.ttf office` |

表のファイル名は利用者が手元のフォントに置き換える。
画像の例ではアウトラインのあるフォントを使う。
一字を直接調べるときは従来どおり `--char U+0041` または `--glyph 26` を使う。

引数なしの `sofel`、`sofel help`、`sofel -h`、`sofel --help` は同じ一覧を表示する。
一覧には各操作の名前と用途、画像の使用例、詳細を開く方法を載せる。
`sofel help NAME`、`sofel NAME -h`、`sofel NAME --help` は同じ詳細を表示する。
詳細には従来のヘルプにあるオプションと表の使用例を載せ、呼び出し方を `sofel NAME` と書く。

統一ヘルプは既存の説明と使用例から組み立てる。
上記のヘルプと render の文字列描画以外は、残りの引数を OS の文字列のまま既存の処理に渡す。
subset 固有の `--help-all` なども従来どおり扱う。
既存の処理には標準エラーもそのまま渡すため、既存の診断には従来の実行ファイル名が出る。
実装時に README の利用例と仕様書の CLI の項目を更新する。

## 文字列の描画

`sofel render --ppem P --text TEXT FILE` は、一引数で受け取った UTF-8 の文字列を、一つのフェイスでシェーピングして一枚の PGM に書く。
同じ文字列をファイルに保存して繰り返し描くときは、`--text TEXT` の代わりに `--text-file PATH` を指定する。
`sofel help render` には、引数の例に加えて `sofel render --ppem 48 --text-file sample.txt font.ttf > sample.pgm` を載せる。
ファイルは UTF-8 で読み、末尾に CRLF または LF があれば一組だけ取り除く。
それ以外の文字は前後の空白も含めて保持し、得られた一行を引数の場合と同じ手順で描く。

初版の文字列描画はアウトラインを白地に黒で描く。
フェイスと可変軸の指定は単字描画と同じ意味で受け付け、シェーピングにも描画にも同じ値を使う。
`--features` は shape と同じ構文を受け付けるので、たとえば `--features=-liga` を付けた画像と既定の画像を比較できる。
`--text` と `--text-file` は統一 CLI だけに追加し、既存の `sofel-render` は変えない。

文字列全体を一つのラン（同じ方向とスクリプトで処理する文字の並び）として shape の既定の方向、スクリプト、言語で処理する。
1 em を 64 × P 単位とし、ppem は P にそろえる。
たとえば 48 ppem の画像を調べるときは、shape に `--font-size=3072 --font-ppem=48` を渡せば同じ単位で配置を読める。
ペンの初期位置を原点とし、出力順に各グリフを「ペン位置＋オフセット」に置いた後、送り幅だけペンを進める。
ペン位置は 1/64 画素単位のまま累積し、描画位置だけを最も近い画素に丸める（ちょうど半画素のときは正の無限大方向）。
横幅には開始位置、終了位置と全グリフのインクを含め、高さにはインクの上下端を含める。
横幅の両端は外側の整数に丸め、幅と高さは最低 1 画素とする。
インクのないグリフでも送り幅だけ進め、重なるインクは出力順にアルファ合成する。
PGM は 8 ビットの P5 形式で標準出力に書き、成功時の終了コードを 0 とする。
画像サイズを表現できない場合やメモリを確保できない場合は、画像を書き始める前に終了コード 1 で診断する。

## 実装しないこと

この ADR では段落の折り返し、双方向テキストのラン分割、フォントフォールバック、文字列のカラー描画、PNG 変換、ギャラリーの生成、フォントの自動取得は扱わない。
手元のフォントと任意の入力を調べる操作は、固定した見本を生成する [ADR 0069](0069-font-render-gallery.md) の採否に依存しない。

## 不変条件

1. 一覧と各操作の詳細は、対応するどのヘルプの呼び方でも同じバイト列を標準出力に書き、標準エラーは空で終了コードは 0 になる。
2. 一覧に載る五つの操作はすべて詳細を開ける。各詳細には該当する使用例が載る。
3. 統一ヘルプと新しい文字列描画を除く既存操作は、同じ引数、入力、ファイル状態なら従来の実行ファイルと標準出力、標準エラー、生成ファイルの内容、終了コードが一致する。
4. 未知の操作、未知のヘルプ対象、`help` の余分な引数では、標準出力は空で終了コードは 2 になる。標準エラーに誤った引数と `sofel help` を示す。
5. 有効な文字列では、画素の位置と濃度が上記のシェーピングと合成の結果に一致する。インクのない入力でも白い PGM を出力する。
6. 文字列入力の指定が複数ある場合（同じオプションの重複を含む）や、文字列入力と `--glyph`、`--char`、`--color`、`--palette` のいずれかを併用した場合は、画像を出力せず標準エラーに理由を書いて終了コード 2 で終わる。不正な UTF-8 や、描画する文字列に CR または LF が残る場合も、画像を出力せず標準エラーに理由を書いて終了コード 2 で終わる。
7. 同じフォントと描画オプションで同じ文字列を渡せば、ファイル入力と引数入力で PGM のバイト列が一致する。
8. テキストファイルを開けない場合や読み込みに失敗した場合は、標準出力を空に保ち、標準エラーにパスと理由を書いて終了コード 1 で終わる。

| 境界の入力 | 期待する結果 |
| --- | --- |
| `--text ""` | 白い 1 × 1 画素 |
| `--text " "` | 送り幅を含む白い画像、高さ 1 画素 |
| `--text A` | 一つのグリフのインクを含む画像 |
| `--text ffi` | 合字を持つフォントではシェーピング後の字形 |
| `--text A --glyph 1` | 入力の指定が重複するため終了コード 2 |
| 空ファイル、または LF 一つだけのファイル | `--text ""` と同じ画像 |
| 前後に空白のある一行、末尾は CRLF | 改行だけを除いた引数と同じ画像 |
| 二行のファイル、または末尾に LF が二つあるファイル | 改行が残るため終了コード 2 |
| `--text A --text-file sample.txt` | 入力の指定が重複するため終了コード 2 |
| 存在しないテキストファイル | 終了コード 1 |
| 引数なし | 一覧 |
| `help render` | render の詳細 |
| `help renderer`、`renderer` | 未知の名前として失敗 |
| `help render extra` | 余分な引数として失敗 |
| `render` だけ | 従来の render と同じ引数不足の終了コード |

## テスト設計

実装前に CLI の統合テストを書き、実行ファイルがない状態で失敗を確かめる。
テスト名には対応する不変条件の番号を入れる。

- `inv1_help_forms` と `inv2_help_examples` で、全操作についてヘルプのバイト列、出力先、終了コードと例を検査する。
- `inv3_command_parity` で同じテストフォントを両方の入口に渡し、五つの操作の結果を比較する。subset は別々の一時ディレクトリで同じ名前に書き、生成物を比較する。render は PGM のヘッダーと画素列も確認する。引数不足と読めないフォントも試す。
- `inv4_unknown_command` で表の誤入力を渡し、診断、標準出力、終了コードを検査する。

- `inv5_text_pixels` では固定フォントで空文字、前後の空白、合字のオンとオフ、結合記号の重なり、右から左に組む語の画素と寸法を期待画像に照合する。
- `inv6_text_usage` では不変条件 6 の各入力について標準出力が空であること、診断と終了コードを確認する。

- `inv7_text_file_parity` では空文字、前後に空白のある文字列、結合記号を含む文字列を、改行なし、LF 終端、CRLF 終端の各ファイルから描き、引数で描いた画像とバイト単位で比較する。
- `inv8_text_file_read_error` では存在しないパスを渡し、標準出力、診断、終了コードを確かめる。

## トレードオフ

シェルの別名でも入力は短くなるが、各自が設定する必要があり、操作の一覧も得られない。
一つの実行ファイルに操作の一覧と使用例を持たせれば、インストールした環境だけで目的の操作を探せる。
その代わり、操作を追加したときは一覧と使用例のテストも更新する必要がある。
