# ADR 0045: 土台の4件の ADR を実装済みとする条件

ステータス: 採択（未実装）

## 文脈

sofel の初期の4件の ADR は、将来扱うフォントの範囲と、機能を加えるたびに守る開発上の約束を定めた。
既に sfnt の読み取り、シェーピング、ラスタライズ、適合テスト、性能計測が動いている。
一方、WOFF2 や古いフォント形式などは個別の設計と実装を待っている。
[ロードマップ](../roadmap.md) には、この段階で土台を実装済みとする条件が未決事項として残っている。

## 実装すること

4件のステータスは、以下の条件を ADR ごとに確かめてから「採択」にする。
既存のステータスに記した後続 ADR への参照を保ち、完了条件の変更先としてこの ADR を示す。

| 対象 | 土台の完了条件 |
|---|---|
| [ADR 0001](0001-project-goal-and-scope.md)　対象範囲 | 少なくとも1個の sfnt フォントについて、公開されているコマンドから文字列をグリフ列に変換でき、グリフを画像に描ける。README と仕様書から現在使える形式と処理を確認できる。 |
| [ADR 0003](0003-crate-layers.md)　クレートの層 | 読み取り、フォント、シェーピング、輪郭、ラスタライズが別のクレートとして動作する。ワークスペースの依存と `unsafe` の検査が通り、`Font` と `ShapePlan` が `Send + Sync` を満たすことを既存のテストで確認できる。C ABI の例外には [ADR 0015](0015-c-abi.md) を適用する。 |
| [ADR 0005](0005-conformance-tests.md)　正しさの基準 | 固定した HarfBuzz のシェーピング結果とサブセットのバイト列、固定した FreeType の輪郭とラスタライズ結果を比較できる。一覧外の失敗と一覧に残った成功の両方を適合テストが検出する。 |
| [ADR 0006](0006-performance-measurement.md)　速さの基準 | ネイティブと wasm の計測の道具が固定した参照実装と結果を照合できる。実機、ツールチェーン、入力、中央値、中央絶対偏差、時間の比を含む両ターゲットの計測記録を参照できる。 |

機能を加えるときは、各段階の ADR でクレートの依存を決め、該当する適合テストと計測項目を足す。
各項目の速度目標と、v1 リリース時に比較結果を記録するロードマップの予定も引き続き適用する。

## 実装しないこと

個別の形式や機能を実装済みとする判断は、その形式や機能の ADR で行う。
この変更では、期待失敗の追加、検査の省略、計測結果の変更は行わない。

## 不変条件

なし。既存の機能と検査に基づいて文書のステータスを更新する手順だけを定める。

## テスト設計

採択後、各行の条件を次の方法で確かめる。
文書だけを変えた PR で CI が実行を省略したジョブは、同じ実装を検査した既存の CI の結果か、手元の実行結果を参照する。

1. [ADR 0001](0001-project-goal-and-scope.md) は README の使い方に沿って、取得済みの sfnt フォントで `sofel-shape` と `sofel-render` を実行する。グリフ列と画像の出力を確認し、対応範囲を仕様書と突き合わせる。
2. [ADR 0003](0003-crate-layers.md) は `sh scripts/check-deps.sh` と `cargo test -p sofel-font -p sofel-shape` の結果を確認する。
3. [ADR 0005](0005-conformance-tests.md) は参照実装を使った Linux と macOS の適合テストの成功と、期待失敗を判定する関数のテスト結果を確認する。
4. [ADR 0006](0006-performance-measurement.md) はネイティブと wasm の `--once` の照合、中央値と中央絶対偏差の単体テスト、および[両ターゲットの計測記録](../benchmarks/2026-11-10-stage2.md)を確認する。この記録は両ターゲットで計測して必要な値を記録できたことの根拠とする。速度目標の達成を評価するときは、[ロードマップ](../roadmap.md) に従い、負荷の高い環境で測った項目を取り直す。

## トレードオフ

土台を運用し始めた時点を明記できる一方、4件のステータスだけでは個々の機能の対応状況は分からない。
利用者は README と仕様書で利用可能な機能を確認し、開発者は個別の ADR とロードマップで残りの段階を追う。
