# ADR 0014: ラスタライズの掃き出しを触れたセルだけにする

ステータス: 採択（未実装）

## 文脈

[ADR 0012](0012-antialiased-rasterizer.md) は、FreeTypeのsmoothのラスタライザと同じ計算で画像を作り、セルの格納だけを変えると決めた。
セルは、帯の幅×高さの密な配列（`cover` と `area` の組）に積み、掃き出しは帯の行ごとに左から累積する。
重なりの印のある輪郭は、4×4の副標本で描くため16倍の費用がかかり、それはFreeTypeと同じだとした。

[ADR 0013](0013-benchmark-harness.md) の最初の記録（[2026-11-10の2段階目](../benchmarks/2026-11-10-stage2.md)）では、重なりの印を持つRobotoFlex-Variableのラスタライズが、ネイティブでFreeTypeの1.5〜4.4倍の時間がかかった。
画素が大きいほど差が開く（12画素で1.54倍、96画素で4.35倍）。
重なりのないフォントでも、96画素では1を超える項目がある（NotoNastaliqUrdu-Regularで1.28倍）。
仕様の目標は、各項目でsofelの時間が比較の相手以下であることである。

原因を、次の順で切り分けた（Apple M1 Max、`cargo run --release --manifest-path bench/Cargo.toml -- --filter RobotoFlex`）。

- 帯の大きさを変えても（`Rasterizer::with_band_cells` に8192、65536、1048576）、96画素の比は4.1〜4.2倍のまま変わらない。帯ごとの描きなおしは原因ではない。
- 掃き出しを止めて（セルを積むだけにして）計ると、96画素で90msが15msになる。時間の大半は掃き出しにある。

FreeTypeとsofelの掃き出しは、次の点で違う。

- FreeTypeは、行ごとにxの順の連結リストで、触れたセルだけを持つ（`gray_sweep`）。セルの間の区間は、同じ被覆率の「span」としてまとめて渡し、被覆率が0の区間は渡さない。
- 重なりのとき、FreeTypeはspanを受けて、標本ごとに `(coverage + 8) / 16` を画素に足し、`sum - (sum >> 8)` で255に止める（`ft_smooth_overlap_spans`）。被覆率が0の標本には何もしない。
- sofelは、帯の密な配列を毎回すべて0にし、すべての標本について被覆率を求め、0の標本も含めて足し込んでいる。重なりのときは、これが画像の16倍の面積に及ぶ。

## 実装すること

数値の計算（24.8への変換、`gray_render_line`、`FT_UDIV`、曲線の分割、`FT_FILL_RULE`、副標本の `(coverage + 8) / 16`）は変えない。
変えるのは、セルの片づけ方と掃き出しの手順だけで、画像はFreeTypeと完全に一致したままとする（[ADR 0012](0012-antialiased-rasterizer.md)）。

### 触れた範囲だけを掃き出す

- 帯の行ごとに、触れた列の最小と最大（範囲）を持つ。`gray_set_cell` にあたる関数でセルを選ぶときに更新する。
- 掃き出しは、行ごとに範囲の中だけを左から累積する。範囲より左のセルはすべて0なので、累積の値も0から始まる。範囲より右は、最後のセルのあとの累積の値（`cover` だけで `area` のない被覆率）が続くものとして、0でなければ行の終わりまで書く。
- 掃き出しながら、範囲の中のセルを0に戻す。帯の配列は、描画のたびに全体を0にしない。配列は、どの描画の終わりにもすべて0になっている。

### 被覆率を求めるのは触れたセルだけにする

- 触れたセルでは、その画素の被覆率（`cover - area` から）と、そのあとの区間の被覆率（`cover` から）の2つを求める。
- 触れていないセルの区間は、直前に求めた区間の被覆率をそのまま使う。

### 重なりのときは画素ごとの合計をとる

- 重なりのときは、画素ごとの合計を16bitの配列に積み、掃き出しの最後に `min(合計, 255)` で8bitの画像にする。
- 区間の被覆率が0でなければ、区間が1つの画素にかかる標本の数を掛けて、まとめて足す。0なら何もしない。
- これがFreeTypeの `sum - (sum >> 8)` と同じ結果になる理由：1画素は16個の副標本からなり、1標本の加算は `(255 + 8) / 16 = 16` 以下なので、合計は256以下である。FreeTypeの式が値を変えるのは、和が256に達したときだけで、それは16個すべてが16のときの最後の加算に限られる。そのため、加える順序によらず、結果は `min(合計, 255)` に等しい。

### データ構造

| 名前 | 型 | 中身 |
|---|---|---|
| セルの配列（既存） | `Vec<(i32, i32)>` | 帯の幅×高さの `(cover, area)`。描画の前後でつねにすべて0 |
| 行の範囲（新） | `Vec<(usize, usize)>` | 帯の行ごとの、触れた列の最小と最大。触れていない行は最小が最大より大きい |
| 画素ごとの合計（新） | `Vec<u16>` | 重なりのときだけ使う。画像と同じ大きさ |

どれも `Rasterizer` が持ち、描画をまたいで使い回す。公開のAPIは変えない。

## 実装しないこと

- FreeTypeと同じ、行ごとの連結リストによる疎なセルの格納。試作では、上の変更だけで重なりのある輪郭も相手以下になったため、格納は密な配列のままとする。
- 浮動小数点やSIMDによる累積（[ADR 0012](0012-antialiased-rasterizer.md) のとおり、完全一致を保つため）。
- 重なりのない96画素でまだ残る差（試作で1.05倍程度）の解消。実装後の記録で残っていれば、計測の記録を添えて別のADRで扱う。
- 輪郭をセルに積む側（線分と曲線の分割）の高速化。

## テスト設計

実装のまえに、次のテストを書いて失敗させる（今の実装で通るものは、変更で壊れないことの確かめとして先に置く）。

- 範囲：1つの帯の中で、触れる列が行ごとに違う輪郭（斜めの三角形、行ごとに幅の変わる図形）で、密な配列をすべて掃き出す参照の実装と同じ画像になることを確かめる。参照の実装はテストの中に置く。
- 片づけ：同じ `Rasterizer` で大きいグリフのあとに小さいグリフを描き、新しい `Rasterizer` で描いた画像と同じになることを確かめる（前の描画のセルが残らないこと）。
- 範囲の右：輪郭が帯の右端より右に出る（列が切り捨てられる）場合と、左端より左に出る場合で、参照の実装と同じ画像になることを確かめる。
- 重なりの合計：16個の副標本がすべて覆われる画素が255になり、部分的に覆われる画素が、標本ごとに `sum - (sum >> 8)` で足す参照の実装と同じ値になることを、重なる2つの四角、細い線、画素の境界をまたぐ図形で確かめる。
- 帯：既存の、帯の上限を変えても同じ画像になるテスト（[ADR 0012](0012-antialiased-rasterizer.md)）が通ることを確かめる。

自動テストにしにくいものは、次のとおり自動で確かめる。

- FreeTypeとの完全一致：既存の適合テスト（`raster:<PPEM>:<グリフ>`、[ADR 0005](0005-conformance-tests.md)）が、期待する失敗の一覧を変えずに通ることで確かめる。
- 速さ：CIの `bench` ジョブの `--once` で照合が通ることを確かめる。時間はCIでは計らず、実装のプルリクエストの記録で、ラスタライズの各項目の比を示す。

## トレードオフ

- 行の範囲と画素ごとの合計の配列のぶん、`Rasterizer` が持つメモリが増える（範囲は帯の行数×16バイト、合計は重なりのときの画像×2バイト）。
- 重なりのときの結果がFreeTypeと一致するのは、副標本が4×4で、1標本の加算が16以下であることに依る。副標本の数を変える場合は、この前提を見なおす。
- 触れたセルの範囲の中に、触れていないセルが多い行（左右に離れた2本の縦線など）では、範囲の中の走査が残る。疎な格納に比べて不利だが、試作の計測では問題にならなかった。
- 試作（このADRの作成のために一時的に書いたもの、未コミット）での計測は次のとおり。照合はすべて通った。

| 項目 | 変更前の比 | 試作の比 |
|---|---:|---:|
| RobotoFlex-Variable 12画素 | 1.54 | 0.92 |
| RobotoFlex-Variable 24画素 | 2.39 | 0.93 |
| RobotoFlex-Variable 48画素 | 3.19 | 0.89 |
| RobotoFlex-Variable 96画素 | 4.35 | 0.84 |
| NotoNastaliqUrdu-Regular 96画素 | 1.28 | 0.93 |
| Roboto-Regular 96画素 | 1.01 | 1.05 |
| Comfortaa-Regular-new 96画素 | 1.09 | 1.06 |
| SourceSerifVariable-Roman 96画素 | 0.87 | 0.91 |
| 上記以外の12〜48画素 | 0.75〜0.94 | 0.80〜0.94 |

  変更前の比は[2026-11-10の記録](../benchmarks/2026-11-10-stage2.md)の値、試作の比は同じ機械で計った値で、時刻が違うため揺れを含む。
  段階ごとには、0の加算を飛ばすだけで96画素が4.14倍から1.89倍に、触れたセルだけで被覆率を求めると1.60倍に、触れた範囲だけを掃き出すと1.43倍に、重なりのときに画素ごとの合計をとると0.84倍になった。
  重なりのないときに広い区間を1回で埋める形（`fill`）も試したが、速くならなかったので採らない。
