# ADR 0041: シェーピングの行ごとの比較結果を集約する

ステータス: 採択（未実装）

## 文脈

[ADR 0020](0020-shaping-foundation.md) の適合テストはHarfBuzzとsofelのシェーピング結果を行ごとに比べる。
追加フォントを含む `f4478df` に直列化とラスタの逐次比較の提案を重ね、適合テストを名前順に2並列で実行した。
その最大観測時の合計RSSは1,925,392 KiBで、`harfbuzz_shape_dump` の実行ファイルだけで1,726,896 KiBを占めた。
`--shape` の既存の実測では529,399行のうち523,621行が一致し、不一致は5,778行だった。

行の識別子はフォント、入力ファイル、方向、機能の組に対して一つである。
従来は一致する行にも識別子、パス、コードポイント、両者の出力のコピーを作り、全入力の比較後まで保持した。
さらに失敗のカテゴリを確認するフォントの表を作るとき、不一致の各行について同じフォントのファイルを読み込んだ。
不一致5,778行に対応するフォントは2種類で、行ごとに読んだ場合の合計は1,246,789,852 byte、パスごとなら1,777,644 byteとなる。

## 実装すること

各組の全行を従来と同じ順序で比較し、比較した行数と、判定や表示に使う不一致行の記録を作る。
従来は行の組を作るときに短い方の行数で終わりうるため、入力、参照とsofelのどれかの行数が違えばエラーにする。
カテゴリの検査にはすべての不一致行を渡す。通常の出力、`SOFEL_SHAPE_VERBOSE` の差分と `SOFEL_SHAPE_SUGGEST` の提案を従来どおり残す。
カテゴリの検査に使うフォントは、一回の判定で不一致があったパスごとに一度だけ読み込む。

## データ構造とアルゴリズム

比較した行数を組ごとに数える。不一致行では行番号、入力コードポイント、方向、両者の出力を保存する。
一行以上を比較してすべて一致した組は、識別子と成功を表す一件で判定できる。
不一致がある組はその全不一致行を入力の順で渡せば、組の成否は同じになる。空の入力では識別子を登録しない。
失敗のカテゴリに使うデータは不一致のフォントのパスを重複排除してから読み込む。

## 実装しないこと

シェーパー、参照CLI、入力の組、期待する失敗の一覧および並列数の変更は対象外である。
`--shape-random` の乱数生成と各scriptの最初の不一致、`--layout-map` の言語システムの比較は以前の方法を使う。

## 不変条件

1. 入力と両者の出力の行数が等しいとき、各行を一度比較し、全行数、不一致の行番号と順序、両者の出力、入力テキストが一行ずつ記録する方式と一致する。
2. 空の組は判定に登録せず、すべて一致した非空の組は成功を一件登録する。不一致を含む組は不一致の全行を登録し、一致行の内容を保持しない。
3. 入力、参照とsofelの行数が一つでも合わない場合は失敗する。入力に終端の改行が一つある場合は空の行を余分に比較しない。
4. 一回の判定で、不一致がある各パスの読み込みを一度だけ試みる。成功したパスのデータを全該当行から参照でき、一致しかないパスを読み込まない。

| 入力 | 比較した行数 | 組の判定に渡すもの |
| --- | ---: | --- |
| 空ファイル | 0 | なし |
| 空行一つ | 1 | 両出力が一致すれば成功一件 |
| 一致だけが複数行 | 全行 | 成功一件 |
| 一致と不一致が交互 | 全行 | 元の順に不一致行すべて |
| どれかの出力が一行多い・少ない | — | エラー |
| 同じパスに不一致が複数 | 全行 | パスの読み込みは一度 |

## テスト設計

I1とI2は空、全一致、全不一致、混在、非ASCIIの入力で、期待する総行数、識別子、行番号、入力コードポイント、両者の出力と判定を照合する。
I3は三系列のどれかが長い・短い場合、終端の改行の有無と空行を調べる。
I4は読み込む関数を差し替えてパスごとの呼び出し回数、成功と読み込み失敗を比べる。
固定した実データで、各モードの件数、カテゴリ、不一致の詳細と順序を照合する。単体と適合全体の2並列について、経過時間と子孫の合計RSSを採取する。

## トレードオフ

全行が不一致の入力では、カテゴリと診断のために全行の詳細が要る。一致が多い入力ほど、この集約で省ける領域は大きい。
実行ファイルごとのRSSは同時実行するテストによって重なるため、適合全体の効果には組み合わせと実行順が影響する。
