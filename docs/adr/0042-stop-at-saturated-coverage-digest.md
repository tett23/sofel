# ADR 0042: Coverageの要約が飽和したら読み取りを終える

ステータス: 採択

## 文脈

[ADR 0020](0020-shaping-foundation.md) のシェーピング計画は、GSUBとGPOSのサブテーブルで照合できるグリフを三つの64 bitマスクで近似する。`add_coverage` はCoverageの全範囲を読み、`Digest::add_range` は三つのマスクがすべて1なら何も書かずに戻る。後続の範囲を読んでも、すでに飽和したマスクは変化しない。

## 実装すること

範囲列を受け取る関数でマスクの更新と走査終了を決める。単一グリフでは各マスクに対応する1 bitを立て、複数グリフでは既存の範囲演算を使う。

## データ構造とアルゴリズム

既存の三つのマスクをそのまま保持する。走査開始時と範囲を追加した後に三つすべてが全ビット1であるかを調べる。飽和した場合はイテレータから次の範囲を取得する前に戻る。

## 実装しないこと

Coverageの公開API、シェーピング計画の寿命、サブテーブルの選択規則の変更は対象外とする。

## 不変条件

1. 同じ範囲列をすべて加えた従来の三つのマスクと一致する。
2. 初期状態が飽和していれば一件も読まず、途中で飽和した場合は後続の範囲を読まない。

| 入力 | 結果 |
| --- | --- |
| 空 | 初期値 |
| グリフ一つ | 各シフトに対応する1 bitを加える |
| マスクの端をまたぐ範囲 | 従来の範囲演算と一致 |
| 飽和に一つ足りない | 次の範囲を読む |
| 飽和した直後 | 次の範囲を読まずに終了 |

## テスト設計

境界をまたぐ単一・複数の範囲と重複する範囲を従来の計算と照合する。入力を取得した回数を記録し、飽和後の先読みを検出する。実用フォントの同じ計画生成を前後で測り、シェーピングの出力を適合テストで検査する。

## トレードオフ

短いCoverageでは走査の短縮が起きず、飽和判定の位置や単一グリフの分岐が実時間に影響しうる。効果は計測して判断する。
