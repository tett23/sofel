# ADR 0055: CLI の COLRv0 描画処理を独自に書き直し、MIT を維持する

ステータス: 採択

## 文脈

[ADR 0023](0023-color-glyphs.md) は、COLRv0 のレイヤーを順に描画してカラーグリフを得る振る舞いを定めた。
[ロードマップ](../roadmap.md)には、CLI の実装が FreeType のレイヤー列挙と描画の制御の流れをなぞっているという判断事項がある。
この ADR では、CLI にある該当処理を、sofel の API と描画結果の仕様から書き直す。

## 調査した事項

`sofel-cli` はワークスペースの MIT ライセンスを継承する。
CLI の `color_layers` は COLR のレコードとパレットの範囲を調べ、有効なレイヤー列を返す。
`render_color` はその列に色を割り当て、各レイヤーのビットマップを `sofel-raster::blend_layer` に渡す。
FreeType から移植した画素合成の算術は、[第三者の著作権表示](../../THIRD_PARTY_NOTICES.md)で `sofel-raster` の項に記録されている。

## 実装すること

`sofel-cli` のライセンス表記を MIT とし、`color_layers` と `render_color` の FreeType 由来の制御を独自実装に置き換える。
実装の根拠には、[ADR 0023](0023-color-glyphs.md)、sofel の各 API の契約、既存の適合テストで観測できるレイヤー列と描画結果を使う。
FreeType のソースや現在の CLI の分岐を逐語的に移し替える方法、既存の制御を別クレートに移すだけの方法は採らない。
実装レビューでは、レイヤー選択、色の解決、描画失敗時の処理をそれぞれどの仕様から導いたかを確認する。

## アルゴリズム

COLR のベースグリフが指す範囲から、描画に使えるレイヤーの列を求める。
色はパレットのエントリまたは前景色から決定する。
フォントのパレット指定が範囲外なら0番を使い、カスタムパレットに対応するエントリがなければ透明な黒を使う。
その列をフォントに記録された順で描画し、画素の合成には既存の `blend_layer` を使う。
有効な列が空の場合とレイヤーの輪郭を描けない場合には、ベースグリフ自身の輪郭によるグレー画像を返す。

## 実装しないこと

`sofel-raster` の合成算術、同クレートの `MIT AND FTL` 表記と帰属表示、COLRv1 の描画は対象外とする。

## 不変条件

1. ベースグリフのレイヤー範囲全体が表に収まれば、`color_layers` は先頭から最初の無効なグリフ番号またはパレット番号の直前までを順に返す。範囲が表を越えれば空列を返す。前景色の指定は有効とする。
2. ベースグリフの輪郭を読み込めて、有効なレイヤー列が空でなく全件を描画できるとき、色画像の位置、寸法、画素列は、指定色で各レイヤーを順に `blend_layer` へ渡した結果に一致する。
3. 有効な列が空、またはレイヤーの描画が途中で失敗したとき、カラー用の出力画像は空になり、戻り値はベースグリフのグレー描画の成否と内容に一致する。ベースグリフ自体を最初に読み込めない場合はそのエラーを返す。

| 入力 | 期待する結果 |
| --- | --- |
| レイヤーが0件 | グレー描画 |
| 有効な前景色レイヤーが1件 | 指定した前景色で描画 |
| フォントのパレット番号が範囲外 | 0番のパレットで描画 |
| フォント上は有効だがカスタムパレットにないエントリ | 透明な黒で合成 |
| 半透明の2件が重なる | フォントに記録された順に合成 |
| レイヤー範囲が表から1件あふれる | 空列となりグレー描画 |
| 有効な1件に続いて無効な番号がある | 有効な1件だけをカラー描画（その輪郭を描ける場合） |
| 1件合成後、次の輪郭の描画に失敗 | 部分画像を破棄しグレー描画 |

## テスト設計

`inv1_color_layers` で表の範囲と番号の境界を検査する。
`inv2_color_pixels` は前景色、フォントのパレット、カスタムパレットを使い、位置、寸法、全画素を比較する。
`inv3_gray_fallback` は空列と途中失敗を区別し、再利用する出力画像に以前の画素が残らないことと、ベースグリフを読めない場合のエラーを確かめる。
公開関数と、その呼び出し元である `sofel-render --color` および C API の `sofel_render_color_glyph` の既存テストを含めて書き直しの前後で照合する。
描画結果を維持する変更なので、独自実装への置き換え自体はコードレビューで確かめる。

## トレードオフ

CLI の独自実装と FreeType 由来の画素合成を区別して記録できる。
同じ描画結果を保つため、正常なフォントに加えて、不正なレイヤー範囲や途中失敗も比較する手間がかかる。
