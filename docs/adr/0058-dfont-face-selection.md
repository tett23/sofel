# ADR 0058: dfont のバイト列からフェイス番号で sfnt を選ぶ

ステータス: 採択（未実装）

## 文脈

[ADR 0001](0001-project-goal-and-scope.md) の第8段階では、Mac のリソース形式に格納された sfnt を読む。
[ADR 0003](0003-crate-layers.md) は、コンテナから sfnt を取り出す役割を `sofel-read` に割り当てている。
dfont と、データフォークにリソース形式の内容を格納したスーツケースを、呼び出し側が渡すバイト列から開けるようにする。

## 調査した事項

`FontFile::new` は単独の sfnt と TTC を識別する。
`Font::new` はコンテナ内のフェイスをゼロ始まりの番号で選び、範囲外では `FontError::IndexOutOfRange` を返す。

`testdata.lock` で固定した HarfBuzz の `DFONT.dfont` は3,505バイトで、リソースマップに `sfnt` と `FOND` が1件ずつある。
`sfnt` のリソース ID は14116で、本体はファイルのオフセット260から2,488バイトを占める。
HarfBuzz の `in-house/collections.tests:1` はこのフォントをフェイス番号0で開く。
[ADR 0005](0005-conformance-tests.md) が想定した dfont 用の入力追加は、固定済みのこのファイルと生成した境界テストで代える。
HarfBuzz の `ResourceMap::get_face` は `sfnt` 型の参照リストを番号順に引く。

## 実装すること

既存の sfnt と TTC の識別を保ち、HarfBuzz が dfont の識別に使う先頭4バイト `00 00 01 00`（データ領域の開始位置256）を持つリソース形式を受け付ける。
ファイル名や拡張子に依存せず、渡されたバイト列だけを使う。
`FontFile` でフェイスを列挙できるようにし、`Font::new`、C API、CLI の既存のフェイス番号指定と、検証器のフェイス列挙に接続する。
適合テストのダンプを含め、コンテナを列挙する既存の呼び出し元にも同じ規則を適用する。

## データ構造とアルゴリズム

リソースマップを参照するビューを持ち、最初の `sfnt` 型レコードの参照リストの順序をフェイス番号に用いる。
同じ型レコードが重複していても、フェイス数と選択には最初のリストだけを使う。
リソース ID や名前で並べ替えない。
マップ内の相対オフセットはそれぞれの基点から計算し、リソース参照の24ビットのデータオフセットはデータ領域の先頭から解釈する。
そこにある4バイトの長さを読み、直後の本体を入力から借用する。
sfnt のテーブルオフセットの基点には、本体の先頭を使う。

各オフセットと長さの加算、参照リストの件数と要素サイズの乗算、宣言された各領域の境界を検査する。
選んだリソースの本体だけを sfnt の読み取り処理に渡す。

## 実装しないこと

macOS のパスから付属のリソースフォークを探す処理、AppleDouble や MacBinary の展開、`FOND` からのフォント合成は対象外とする。

## 不変条件

1. 最初の `sfnt` 型レコードの参照数を N とし、その型がなければ N を0とする。このとき、フェイス数は N であり、番号 i（0 ≤ i < N）のテーブル内容は参照リストの i 番目の本体を単独の sfnt として読んだ結果に一致する。
2. 有効なマップで番号 i ≥ N を `Font::new` に渡すと `FontError::IndexOutOfRange` になる。
3. 必要なマップの参照や選んだリソースが宣言領域を越える場合は読み取りエラーとなる。隣接するリソースのバイトで不足分を補わない。

| 入力 | 期待する結果 |
| --- | --- |
| 空の入力 | 読み取りエラー |
| 有効なマップに FOND のみ | 0フェイス、番号0は範囲外 |
| sfnt が1件、ID は14116 | 番号0で開き、番号1は範囲外 |
| 異なる sfnt が2件、ID は逆順 | 番号0と1で参照順に開き、番号2は範囲外 |
| sfnt 型レコードが2個で各リストに1件 | 1フェイス、番号0で最初のリストの本体を開く |
| sfnt 本体がデータ領域の末尾にちょうど収まる | 読み取り成功 |
| 本体の宣言長が1バイトあふれる | 読み取りエラー |

## テスト設計

`inv1_dfont_faces` は生成したリソースマップで参照順と各テーブルの内容を検査する。
`inv2_dfont_face_index` は0件、1件、2件で最初の範囲外番号を検査する。
`inv3_dfont_bounds` はマップとデータ領域の切り詰め、リソースの外を指す sfnt のテーブルが読み取れないことを検査する。
実装前に正常な dfont の読み取りが失敗することを確かめる。
[ADR 0005](0005-conformance-tests.md) に従い、生成した複数フェイスの入力で FreeType の文字対応とメトリクスとも照合する。
固定済みの `in-house/collections.tests:1` が HarfBuzz の期待するグリフ列と一致した段階で、[ADR 0044](0044-shaping-conformance-exceptions.md) の `dfont` の期待失敗を一覧から外す。
実装時に仕様書と README の対応形式を更新し、ロードマップに適合テストの結果を反映する。

## トレードオフ

入力をメモリ上のバイト列にそろえると、同じテストデータと実装を macOS、Linux、wasm で使える。
別のフォークにしかデータがないファイルの場合、呼び出し側でその内容を取り出して渡す必要がある。
