# ADR 0065: 旧形式と Web フォントを既存のフェイスとして開く

ステータス: 採択（未実装）

## 文脈

圧縮方式と内側のフォント形式を独立に扱うと、文字検索から描画まで同じフェイスの操作を使える。

## 調査した事項

[ADR 0001](0001-project-goal-and-scope.md) は Type1 の AFM と PFM、旧ビットマップ形式、圧縮形式を対象に含む。
[FontFile の読み取り](../../crates/sofel-read/src/sfnt.rs)には sfnt、コレクション、dfont の分岐がある。

## 実装すること

外側の gzip、LZW、bzip2 を展開してから署名に応じてドライバを選ぶ。
WOFF は表ごとに展開し、WOFF2 は Brotli 展開後に変換済みの glyf、loca、hmtx を再構成する。
素の CFF、CEF、Type1 の PFA と PFB、CID、Type42、PFR、BDF、PCF、FNT、FON を共通のフェイス番号、cmap、メトリクス、輪郭またはビットマップの操作へ接続する。
Type1 の Multiple Masters と AFM、PFM の付加メトリクスを扱う。
開いたフェイスに AFM または PFM を付加し、グリフ対のカーニングを問い合わせられるようにする。
各デコーダで出力長とオフセットの算術を検査し、検証器で破損位置を報告する。

## 実装しないこと

WOFF と WOFF2 の書き出しは [ADR 0070](0070-webfont-encoding.md) で扱う。

## 不変条件

1. 同じ入力、フェイス、サイズ、ストライク（収録された固定サイズ）で得る文字対応、送り、グリフ対のカーニング、輪郭またはビットマップは FreeType と一致する。
2. 宣言長の算術があふれる入力や必須データの欠落を成功として返さない。

| 境界の入力 | 期待する結果 |
| --- | --- |
| フェイス0、最後のフェイス、件数と同じ番号 | 有効な番号で条件1を満たし範囲外は失敗 |
| WOFF の非圧縮表と圧縮表が混在、WOFF2 の変換ありとなし | 各フェイスで条件1を満たす |
| 必須の圧縮データが1バイト不足、展開先の範囲があふれる | 条件2を満たす |

## テスト設計

I1_font_driver は各形式の正常サンプルが参照ビルドで開くことを先に確かめる。
WOFF は表を、WOFF2 は再構成した表の内容と公開操作の結果を照合する。
ストライクの有無を比較する。
AFM と PFM の付加前後で、登録されたグリフ対と未登録のグリフ対のカーニングを照合する。
AFM の登録ペアを通常のシェーピング入口にも渡し、カーニングが送りに反映されることを確かめる。
I2_decode_bounds は短い合成入力で切り詰めと長さの境界を検査する。
旧形式の実フォントは [ADR 0005](0005-conformance-tests.md) に従ってライセンスと取得元を決める。

## トレードオフ

形式ごとに必要なテストフォントと参照ビルドの構成が増える。
共通の操作を使うため既存の描画と適合テストを再利用できる。
