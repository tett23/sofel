# ADR 0062: レイアウトの問い合わせでサイズと軸座標を引き継ぐ

ステータス: 採択（未実装）

## 文脈

基準線、合字のキャレット、数式の配置を呼び出し側で使うには、シェーピングと同じスケールで値を取り出す必要がある。

## 調査した事項

[ADR 0017](0017-base-baselines.md) は Device 表によるサイズ別の補正を残した。
HarfBuzz の合字キャレット API は開始位置と格納件数を受け取る。
MATH の組み立て API は部品列とイタリック補正を返す。

## 実装すること

GPOS、GDEF、BASE、MATH で同じ Device 評価を使う。
ピクセル単位の補正には対象方向の ppem を、VariationIndex にはインスタンスの座標を渡す。
GDEF の合字キャレットと MATH の定数、カーニング、異体グリフ、組み立て部品を Rust と sofel の C ABI で公開する。
MATH 表の有無、グリフのイタリック補正、アクセントの取り付け位置、伸長形の判定、接続部の最小重なりも公開する。
列を返す C API は開始位置、容量、格納件数と総数を区別する。
スタイル値は同じフォント位置で hb_style_get_value と照合する。

## 実装しないこと

JSTF による行の均等割り付けはシェーピング後の行組みなので本提案の対象外とする。

## 不変条件

1. 各方向の値は同じ軸座標、ppem、スケールを指定した HarfBuzz の値と一致する。
2. 部分取得の総数、格納件数、各要素は対応する HarfBuzz API と一致し、出力容量の外を書き換えない。

| 境界の入力 | 期待する結果 |
| --- | --- |
| ppem が0、補正の下限直前、上下限ちょうど、上限直後 | 各サイズで条件1を満たす |
| 開始位置が先頭、末尾、末尾の次。容量が0、1、全件 | 条件2を満たす |

## テスト設計

I1_device_query は横縦で異なる ppem と非既定座標を設定して基準線、キャレット、MATH、スタイルを比較する。
MATH 表がない場合と、表はあるが対象グリフの記録がない場合の戻り値も照合する。
I2_query_page は C の番兵付きバッファで部分取得を試し、連結した列を全件取得と比較する。

## トレードオフ

共通の補正処理を使うには、各問い合わせから方向とサイズを明示して渡す必要がある。
