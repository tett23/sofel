# ADR 0077: Noto Color Emoji の二形式で笑顔と ZWJ 列の描画を検査する

ステータス: 採択

## 文脈

[ADR 0069](0069-font-render-gallery.md) のギャラリーで、同じ絵文字を異なる形式のフォントで見比べたい。
[ADR 0072](0072-color-gallery-acceptance.md) のカラー見本に、実際の絵文字と、複数の文字を一つのグリフにするケースを加える。

## 調査した事項

sofel のコミット `0a8d0abb` で Noto Color Emoji v2.047 のフェイス 0 を 109 ppem で描いた。
CBDT 版は CBDT と CBLC を、COLRv1 版はバージョン 1 の COLR と CPAL を含む。
単字は 😀（U+1F600）、文字列は 👩‍💻（U+1F469 U+200D U+1F4BB）とした。
どちらの版も文字列は一つのグリフになり、四つの出力すべてに不透明度が正の有彩色画素があった。

| 形式 | 😀 のグリフ ID と画像寸法 | 👩‍💻 のグリフ ID と画像寸法 |
| --- | --- | --- |
| CBDT | 883、136 × 128 | 2269、136 × 128 |
| COLRv1 | 1780、121 × 117 | 1205、124 × 123 |

同じ順で、PAM ヘッダを除いた RGBA 画素列の CRC-32 は CBDT 版が `f26c4dc6`、`532b95b4`、COLRv1 版が `88a3e34c`、`58240de7` だった。

同コミットの `tools/font-gallery/src/sheet.rs` では単字欄の幅が 128 画素なので、CBDT 版の単字は上限を 8 画素超え、カードの生成が失敗する。

## 実装すること

公式 v2.047 の二つのフォントと同梱ライセンスを固定し、既存の取得手順で検証する。
ギャラリーに各形式一枚のカードを加え、単字欄には 😀 を文字指定で、文字列欄には 👩‍💻 をシェーピングして描く。
どちらもフェイス 0、既定パレット、109 ppem を使う。
単字欄を最低 136 画素に広げ、文字列欄には既存の見本が収まる幅を確保する。

## 実装しないこと

フォント本体と生成画像はテストデータの取得先とギャラリーの生成先に置く。
絵文字全体の適合判定はこの検査の対象外とする。

## 不変条件

1. 各カードの単字と文字列は上表の寸法で描かれ、文字列のグリフ ID 列は上表の一要素だけを含む。
2. 各画像の RGBA 画素列の CRC-32 が調査時の値と一致し、ギャラリーの専用欄に全画素が等倍で収まる。

| 境界の入力 | 期待する検査結果 |
| --- | --- |
| 文字列が 0 グリフまたは 2 グリフ | 条件 1 で失敗 |
| 期待する 1 グリフ | ID と寸法が一致すると条件 1 に合格 |
| 透明画素のみ、または可視画素がすべてグレー | 条件 2 で失敗 |
| 単字欄が幅 136、画像幅 136 または 137 | 136 は収まり、137 は配置エラー |

## テスト設計

実装前にギャラリーのカラー回帰テストに `i1_i2_noto_color_emoji` を加え、二形式の登録がない状態で失敗を確かめる。
文字列の ID 列、各画像の寸法と RGBA の CRC-32を検査し、生成された一覧 PNG の該当領域を単字と文字列の描画結果に照合する。
文字列欄にはギャラリーと同じ白背景のアルファ合成を適用する。
既存カードも含めたギャラリーを生成し、CI のギャラリー検査で新しいケースを実行する。

## トレードオフ

二形式を同じ ppem で描くと字形と余白を直接見比べられる。
フォントの更新でグリフ ID、寸法、画素値が変わったときは、新しい出力を確認して期待値を更新する必要がある。
