# ADR 0064: ヒンティングと描画モードを独立に指定する

ステータス: 採択（未実装）

## 文脈

同じグリフでもヒンティングで輪郭と送りが変わり、描画モードでビットマップの表現が変わる。

## 調査した事項

[ft-dump](../../tools/ft-dump/ft-dump.c) の通常描画はヒンティングを無効にして FT_RENDER_MODE_NORMAL を指定する。
[参照ビルド](../../tools/ft-dump/build.sh)のモジュール一覧には SDF がない。

## 実装すること

ロード時に TrueType v35 と v40、CFF、Type1、CID のネイティブヒンタ、自動ヒンタ、ヒンティングなしを選ぶ。
ヒンティングターゲット（NORMAL、LIGHT、MONO、LCD、LCD_V）はロード時に指定し、描画モードは描画時に指定する。
可変フォントの cvar、幻の点、グリッドに合わせた送りをロード結果に反映する。
この結果からモノクロ、グレースケール、水平と垂直の LCD、SDF の描画を選ぶ。
LCD はフィルタと Harmony の各構成を区別し、SDF は輪郭入力とビットマップ入力を区別する。
描画結果には画素形式、幅、行数、原点、行の配置を保持する。

## 実装しないこと

OS のディスプレイ設定の検出は対象外とする。

## 不変条件

1. 同じフェイス、グリフ、軸座標、サイズ、ロード指定で輪郭点、タグ、輪郭終端、送りが FreeType と一致する。
2. 同じ描画構成では画素形式、寸法、原点、上から順に読んだ有効画素が FreeType と一致する。

| 境界の入力 | 期待する結果 |
| --- | --- |
| 空輪郭、1輪郭、同一グリフで v35 と v40 を切り替える | 各ロード結果が条件1を満たす |
| モノクロの幅7、8、9画素、垂直 LCD、負の pitch のビットマップ | パディングを除く論理画素で条件2を満たす |

## テスト設計

I1_hint_outline は描画前のスロットを比較し、I2_render_mode は既知の正常グリフを各参照モードで描けることを確かめてから比較する。
LIGHT と NORMAL のそれぞれでロードしてから同じ LCD モードで描き、各段階を比較する。
両方の実装が未対応エラーを返すケースを描画成功として数えない。

## トレードオフ

参照ビルドごとの LCD 構成を固定する費用がかかる一方、ロードと描画のどちらに差が出たか特定できる。
