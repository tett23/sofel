# サブセット化の計測（2026-11-10）

[ADR 0022](../adr/0022-subsetting.md) の「計測」の記録（5段階目）。
項目、照合、計測の方法は [ADR 0013](../adr/0013-benchmark-harness.md) と [ADR 0006](../adr/0006-performance-measurement.md) のとおり。
時間は1回あたりの中央値（±中央絶対偏差）、単位はマイクロ秒。比が1未満ならsofelが速い。

## 項目

- `subset (N glyphs, retain-gids)`：Golemの使い方。`ja-runs.txt` と `en-paragraph.txt` の文字をcmapで引いたグリフ、グリフID 1、最後のグリフを、`RETAIN_GIDS` で残す。
- `subset (N characters)`：同じ2つの文章の文字（2322字）を、既定のフラグで残す。
- sofelは `Input` を作って `subset` を呼ぶ。HarfBuzzは `hb_subset_input_t` を作って `hb_subset_or_fail` と `hb_face_reference_blob` を呼ぶ。どちらも出力のFNV-1aのハッシュを求め、計測の前に一致を確かめる（入力の作成とハッシュの計算は両者の時間に含まれる）。
- フォントは `test/subset/data/fonts/` の Roboto-Regular.ttf（glyf）、SourceHanSans-Regular_subset.otf（CIDキーのCFF）、NotoNastaliqUrdu-Bold.ttf（大きなGSUBとGPOS）。前処理つきの項目は、前処理の段階（11段階目）で足す。

## 環境

- 機械：Apple M1 Max、メモリ64GB
- OS：macOS 27.0（26A428）
- Rust：rustc 1.99.1（58cf8f9c3 2026-10-13）
- Cのコンパイラ（ネイティブ）：Apple clang、`-O2 -DNDEBUG`
- wasm：wasi-sdk 34、wasmtime 50.0.1（`-W exceptions=y`）
- 比較の相手：HarfBuzz 15.1.0（`testdata.lock`。`harfbuzz-subset.cc` の単一の翻訳単位）
- sofel：[ADR 0022](../adr/0022-subsetting.md) の5段階目のブランチ（`implement-adr-0022-subset-5-capi`、1〜4段階目を統合した d5f6a72 に対する変更）

**注意**：計測中の機械は、ほかの作業で負荷が高かった（計測の前後のload averageは、1分の値で7〜15、15分の値で10〜11）。比は目安にとどまる。
照合（`--once` と同じ結果の比べ合わせ）は、ネイティブとwasmですべて通った。

## 所見

- 出力はすべての項目でHarfBuzzとバイト単位で一致した。
- 時間は、NotoNastaliqUrdu-Boldのグリフの項目（5グリフ）を除き、HarfBuzzより遅い（ネイティブで1.3〜4.3倍、wasmで1.3〜3.9倍）。最も遅いのは、Source Han Sansの1918グリフを `RETAIN_GIDS` で残す項目（ネイティブで4.32倍）で、Golemの日本語のフォントの使い方に当たる。
- 5段階目は機能（C ABIと突き合わせ）の段階で、速さの改善はしていない。[ADR 0006](../adr/0006-performance-measurement.md)の目標（各項目で相手以下）に届かせるには、CFFのサブセット化と直列化の費用を調べる必要がある。前処理（11段階目）は、同じフォントを繰り返しサブセット化する費用を下げる。
