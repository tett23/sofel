# HarfBuzzの塗りの参照出力の保持量

2026年11月11日、[ADR 0043](../adr/0043-stream-harfbuzz-paint-records.md) のグリフ単位の比較を追加フォント導入後の `f4478dfebbae0bc1110bb011fffd22b99cfdbe93` で測った。
適合全体の名前順2並列でシェーピングの比較結果を集約した後、最大観測時の1,470,320 KiBのうち1,392,784 KiBを `harfbuzz_color` が使っていた。

## 出力の内訳

旧方式のテストで `Command::output` が取得した標準出力の長さと容量を記録した。
固定コーパス全体で、24件の既知の塗りと92フォントを合わせて300回の呼び出しがあった。
92フォントの `--paint` が返した総量は816,991,187 byteで、`--color` は1,142,382 byte、`--extents` は638,476 byteだった。
既知の塗りでは `--paint=0` が6,284,727 byte、`--paint=0.2` が15,297 byte、`--paint=0.3` が49,234 byteだった。

最大の出力はHarfBuzzのテストフォント `49d296d4b92d7dbe2f354ac70fca3e32cbd4a936` と `clusterfuzz-testcase-minimized-hb-raster-fuzzer-5513551012495360` の `--paint` だった。
両方とも403,411,768 byteの出力に536,870,912 byteの容量があり、パース後の663件の塗りの本文にも合計403,400,876 byteを保持した。
最長の本文はグリフ111の4,349,994 byteだった。これらは長さと容量で、RSSは別にプロセスツリーから観測した。
全78,225件の判定に最後まで保持した識別子と詳細の文字列の容量の合計は、それぞれ13,648,522 byteと1,812,900 byteだった。

新方式は `--paint` の標準出力をパイプで読み、一つのグリフの本文を完成させてsofelの出力と比べ、次の本文で同じ領域を使う。
既知の塗りでも同じパーサーを通し、指定した一件を選ぶ。
参照プロセスの終了前に得た判定はその呼び出しに属する配列に置き、全フォントの照合では非ゼロで終了した呼び出しを従来どおり除外する。

## 実行条件

Apple M1 Max、64 GiB、macOS 27.0（26A428、arm64）、Rust 1.99.0で測った。
ビルドには `CARGO_BUILD_JOBS=4 CARGO_INCREMENTAL=0 CARGO_PROFILE_RELEASE_DEBUG=0` を指定し、取得済みの同じ参照フォントとHarfBuzzを使った。
単体の計測では `SOFEL_FAILED_ITEMS` に実行ごとに別のファイルを指定した。
実時間は `/usr/bin/time -p` の `real`、ピークRSSは `scripts/measure-process-tree.sh` で観測した子孫を含む合計の最大値である。
共有ページは各プロセスで数え、採取の間の瞬間的な最大値を取り逃しうる。

```sh
SOFEL_FAILED_ITEMS=failed-items.tsv /usr/bin/time -p \
  sh scripts/measure-process-tree.sh TEST_BINARY --nocapture --test-threads=1
```

先行テストは実装前に読み取り関数が未定義で失敗し、実装後に3件とも通った。
読み取り幅1、2、7、8192で既存のパーサーと同じフェイス、パレット、ppem、グリフと本文を順に受け取った。
空、行数不足、不正ヘッダーとフェイス終端の欠落、途中で失敗する読取り、参照プロセスの0・非ゼロ終了も確認した。

単体では両方式を2回ずつ走らせ、ピークRSSは変更前の1,391,600〜1,394,480 KiBから285,664〜285,984 KiBになった。
平均したピークRSSの減少率は79.5%だった。実時間の範囲は重なり、両方式とも12秒前後だった。
すべての実行で92フォントの78,225件を比較し、既知の24件が失敗、テスト自体は終了コード0だった。
各実行の `SOFEL_FAILED_ITEMS` は24行、4,620 byteで、SHA-256 `414747b3a267d7bc6ec1918e32da7100809f8957571205776df16268efa532d8` まで4回とも一致した。

## 名前順2並列の適合全体

適合全体は、直列化、ラスタ、輪郭の逐次比較と、シェーピング比較の行の集約を共通して適用したworktreeで測った。
名前順で同じ40本を `xargs -0 -n 1 -P 2` に渡し、各バイナリを `--nocapture --test-threads=1` で実行した。
コンパイルを事前に終え、各回の時間にはCargoの更新の確認、各バイナリの計測用ラッパーと最後のdoctestを含めた。
1回目には、カラーの変更を入れる直前に同じworktreeで測ったシェーピング集約後の値を使った。
全40本を保存してからカラー比較を変更し、4回目には保存した旧版40本を同じ順で再実行した。

| 順 | 方式 | 実時間 | ピークRSS | 観測回数 |
| ---: | --- | ---: | ---: | ---: |
| 1 | 変更前 | 114.05秒 | 1,470,320 KiB | 653 |
| 2 | 変更後 | 120.17秒 | 692,128 KiB | 673 |
| 3 | 変更後 | 120.87秒 | 589,568 KiB | 671 |
| 4 | 変更前 | 133.56秒 | 1,430,608 KiB | 709 |

適合全体についても、変更後の両回のピークRSSが変更前の両回より小さく、各方式2回の平均では55.8%減った。
変更前のピークに占める `harfbuzz_color` のRSSは1,392,784 KiBと1,385,248 KiBだった。
変更後のピークは両回とも別の二つのテストが重なった時点で、`harfbuzz` は546,112 KiBと442,688 KiB、`harfbuzz_shape_dump` は127,088 KiBと127,872 KiBだった。
変更後の2回の実時間は、変更前の2回の間に収まった。GitHub Actionsのworkflow完了時間は未測定である。

4回とも全40本とdoctestが成功した。既存の105件に先行テスト3件を加え、変更後は108件が成功した。
照合内容の報告139行は、同じ実行ファイル内の順序も含め4回とも一致した。

計測とは別に、項目を作った順に識別子と成否を1行ずつ書き出す診断用の実行ファイルを作った。
変更前後とも78,225行、8,393,672 byteで、`cmp` で全文が一致した。SHA-256は `75bd0e0f0a6744022af50464ed9350cd66b9e77dbd4944588f8b75f7ab48c49b` である。
この比較のファイルへの書き込みは単体と全体のRSS・実時間の測定から外した。

## 生の記録

単体のworktreeの `target/evidence/` に `output-volumes.json`、4回の標準出力、標準エラー、失敗詳細ファイル、`{before,after}-case-ids.tsv` と `case-trace-result.log` を保存した。
全体のworktreeの `target/evidence/` に `0043-full-comparison.json`、`0043-suite-hashes.json` と `fixed-{0041,0043-b1,0043-b2,0043-a2}*` を保存した。各回の投入順、実行ファイルの開始・終了、最大観測時のプロセス別RSSを含む。
