# ラスタ適合テストの逐次比較（2026-11-11）

[ADR 0037](../adr/0037-stream-raster-reference.md) の提案をローカルで測った。
同じFreeType参照とフォントを使い、グリフ数、画素の比較、期待する失敗の判定を維持して、参照出力と成功ケースの保持方法を変えた。

| ラスタ適合テスト単体 | 比較件数 | 失敗件数 | 実時間 | 子孫を含むRSSの最大観測値 | 採取回数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 変更前：全文と全ケースを保持 | 532,833 | 0 | 35.96秒 | 806,512 KiB | 248 |
| 変更後：グリフ単位で比較 | 532,833 | 0 | 26.59秒 | 17,616 KiB | 184 |

RSSの最大観測値は97.8%、実時間は26.1%減った。
各方式を1回ずつ測った結果であり、繰り返し実験の平均ではない。
ラスタライザ本体の処理は変えず、参照出力の全文、全グリフの行を格納したマップ、全成功ケースの識別子の保持を適合テストから除いた。
終了状態が非ゼロの参照呼び出しの結果は、従来と同じく件数にも判定にも含めない。

## 条件と再現方法

macOS 27.0（26A428）のarm64、rustc 1.99.0（b940084d7）で、コミット `92d9dc086f8c2fb6371898cb627545b07bbd3ba1` と同じコミットに未コミットの変更を加えた作業版を比べた。
FreeTypeは両方とも同じ `ft-dump` 実行ファイル（SHA-256 `7c751a54ba15b7e1573c562d42f3be8140eef38450044e80a0f8277137f48bd4`）を使用した。
テストは固定HarfBuzzコーパスの対象フェイスについて12、24、48 ppemの全グリフを比較する。

各版を次の条件でビルドし、出力されたテスト実行ファイルをそれぞれ別名で保存した。
コンパイル時間と追加した境界テストの時間は数値に含めていない。

```sh
CARGO_BUILD_JOBS=4 CARGO_INCREMENTAL=0 CARGO_PROFILE_RELEASE_DEBUG=0 \
  cargo test --release -p sofel-conformance --test raster --no-run
/usr/bin/time -p sh scripts/measure-process-tree.sh TEST_BINARY \
  rasters_agree_with_freetype --exact --nocapture --test-threads=1
```

`TEST_BINARY` は各版の保存済み実行ファイルに置き換える。
時間は `/usr/bin/time -p` の `real`、メモリは `scripts/measure-process-tree.sh` の `peak_tree_rss_kib` を使った。
どちらも終了状態は0だった。
RSSは0.1秒間隔を目標にプロセスツリーを採取した合計値であり、共有ページを重複して数え、採取間の瞬間的な最大値は見逃し得る。
OSが予約した仮想アドレスの量や物理メモリの厳密なピークを表す値ではない。

実行条件を揃えるため、測定時は他の担当にビルドとベンチマークのCPU使用を止めてもらった。
ただし、共有マシン全体の負荷は制御していない。
適合テストの2並列は維持しており、ここで計測した単体の削減率をworkflow全体の効果としては扱わない。
提案の変更後のCI完了時間は未測定である。

## 振る舞いの確認

変更前後で同じ53万2,833件の画素照合がすべて成功した。
別に、1バイト幅を含む読み取りの区切り、グリフを一つずつ渡す順序、重複・不足・末尾の欠落、読み取り失敗、空出力と参照プロセスの異常終了、期待する失敗を使う判定を5件のテストで確かめた。
既存の正方形のラスタ参照テストも成功し、`cargo clippy --release -p sofel-conformance --test raster -- -D warnings` は終了状態0だった。
